### 2.3 为什么「保留 H6」的反向证据

`fast_qr` 侧这 7 个便捷构造是 `const fn`，**零运行时成本**，且是参考 crate 的公开面
（`src/module.rs`，逐条 `#[must_use] pub const fn`）。本仓库作为**逐位移植**，
保留同形 API 有「便于对照阅读」的收益，只是 MoonBit 无法把函数体内联为零成本常量的
*符号* 层面——它仍会出现在 `.mbti` 里。

**故给出可选的两种口径，由维护者择一（本文不预判）**：

| 口径 | 做法 | 收益 | 代价 |
|------|------|------|------|
| **A. 对齐参考（推荐）** | 保留 H6，并把它**用起来**（见 §3.1 的 `QRCode` 访问器） | 与 `fast_qr` 公共面一一对应，移植可读性最好 | `.mbti` 稍宽 |
| **B. 只留最小面** | H1–H6 全删，只留 `new` + `data` | 公共面最窄，无障碍 | 与参考不再逐项对应，后续移植比对需查表 |

> 若采 B，务必同步更新 `docs/moonbit-实现布局与文件职责.md` 与 `docs/移植参考/专有概念/module.md` 的对照表。

## 3. 代码侧：不是死代码，而是结构性缺口（P1）

### 3.1 缺口根因：`QRCode` 无法从公共 API 获得

`QRCode` 是 `pub(all) struct`，**所有字段公开**，但仓库内没有任何
`.mbt`（含测试）**构造字面量**——全部经由 `QRCode::default(size)` /
`QRBuilder::build()` 取得。而：

- `QRCode::default(size)` 造出的是**空矩阵**（全亮、元数据全 `None`），README 从未提及它是公共 API；
- `QRBuilder::build()` 要求先有一份 `Array[Byte]`，且**必然触发完整编码管线**。

后果：宿主拿到 `QRCode` 之后，下列「读/改」能力在**纯库调用口径**下实际不可达，
只能被测试用（测试同包，可直接用 `QRCode::default`）：

| 能力 | 符号 | 现状 | 参考 fast_qr |
|------|------|------|--------------|
| 逐格读 | `QRCode::get` | 有，但先得有 `QRCode` | `Index<usize>` 切片 |
| 逐格改（不可变） | `QRCode::set` | 同上 | `IndexMut<usize>` |
| 元数据快照 | `QRCode::meta` | 同上 | 字段直接读（`pub`） |
| 版本构造 | `QRCode::for_version` | 同上 | `QRCode::default(size)` |
| 形状按名选 | `Shape::from_name` | 有，但 CLI/宿主无入口演示 | `From<String> for Shape` |
| ECL 显示 | `ECL::to_char` | 有，无宿主入口 | `Display for ECL` |
| SVG 配色 | `SvgBuilder::module_color` | 有，但 **README「快速开始」示例就用了它**，而 `cmd/main` 只调 `default()` | `Builder` trait |

> **README 与实现不一致**：README「快速开始」给出
> `SvgBuilder::default().module_color(...).background_color(...).shape(...)` 的完整链式示例，
> 但 `cmd/main`（唯一演示入口）只跑 `SvgBuilder::default().to_str(qr)`。
> 要么把示例落到 CLI，要么把示例改成 `default()` 口径——**两者必须一致**。

**建议（P1，单独立项）**：新增一个**只读出口**让宿主拿到可用的 `QRCode`：

```
QRCode::empty(version : Version) -> QRCode     # 公开的「空矩阵」构造（= 现 for_version，去掉 ? 元数据歧义）
QRCode::from_matrix(size, data) -> QRCode      # 可选：宿主自建矩阵（需校验 size*size <= QR_MAX_MODULES）
```

并把 `QRCode::meta` / `get` / `set` / `Version::width` / `Shape::from_name` / `ECL::to_char`
在 README 的「公共 API 一览」中**列入对外契约**，同时把上述链式示例落到 `cmd/main`。
这样 §2.4 的 6 个「能力缺口」符号会立刻变成**有生产引用**，README 与 CLI 也自动一致。

### 3.2 `QRCode::build_fixed` 的层级归属（P2）

`build_fixed`（`lib/qr_build.mbt:109`）是 `QRCode::build(mask=Some(m))` 的等价路径，
但 `build` 内部**没有调用它**——两条路径的 `encode`/`structure`/`create_fixed_qr` 三行
是**逐字复制**的。这不是死代码，但有**双份实现**风险：改一处漏一处会静默漂移。

**建议**：让 `QRCode::build` 的 `Some(m)` 分支直接委托 `build_fixed(...)`，
把 `build_fixed` 降为 `fn`（非 `pub`），或保留 `pub` 但由 `build` 复用。
判定口径：改完后 `lib/pkg.generated.mbti` 应只剩 `QRCode::build`（若降级），
`cmd/bench --dump` 三点 sha256 不变（`bash scripts/diff-gate.sh`）。

### 3.3 明确建议删除的「无信息量」符号（P0）

| 符号 | 理由 | 替代 |
|------|------|------|
| `module_dark()` | 零引用，语义 = 字面量 `true` | 直接用 `true` |
| `module_light()` | 唯一调用点的语义 = `false` | 用 `Module::data(false)` |
| `ecl_default()` | 语义 = `ECL::Q`，零生产引用 | 用 `ECL::Q`（并在 `select_capacity` 注释里点名默认值） |
| `SvgBuilder::new()` | 与 `default()` 完全等价（body 就是 `default()`） | 用 `SvgBuilder::default()` |
| `QR_MAX_WIDTH` | 零生产引用；参考侧也是 `pub(crate)` | 降为模块内 `let`（或与 `QR_MAX_MODULES` 二选一） |

> **不删**：`QRCode::get/set`、`Module::data/dark/set/toggle`、`Module::byte` 的 `pub` 身份——
> 见 §3.1，它们是能力出口，删了会让宿主彻底无法读矩阵。

## 7. 执行纪律（务必遵守，否则会破坏现有门禁）

1. **一次一个主题、单独 PR**：代码清理（§2/§3）与文档重构（§6）**不要混在一个 PR**，
   否则回滚代价高、评审难。
2. **删除前先跑三件套**：
   ```bash
   export PATH="$HOME/.moon/bin:$PATH"
   moon fmt && moon info && moon check --deny-warn && moon test
   bash scripts/test-scale.sh && bash scripts/docs-link-check.sh
   ```
3. **`lib/**` 改动前确认工作区干净**：`bash scripts/test-audit.sh mutation` 会
   `git checkout -- lib/` 还原，**未提交的改动会被一并清掉**（AGENTS.md §三.4 陷阱）。
4. **小步提交**：每完成一处有意义的改动即 commit（AGENTS.md §三.5）。
5. **改公共面必须同步**：
   - `lib/pkg.generated.mbti` 是构建产物（gitignore），**不要提交**；
   - API 增删须同步 README「公共 API 一览」+ `docs/moonbit-实现布局与文件职责.md`；
   - 新增/删除文档须同步 README 索引表，否则 `docs-link-check.sh` 会红。
6. **不要为了「看起来干净」删有信息量的历史**：S9b 的「已否决项」、S10 的「偏差记录」
   是**防止重复踩坑**的资产，属**保留**而非冗余。
