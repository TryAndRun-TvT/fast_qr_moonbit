## 0. 结论先行

1. **大版本（V40）瓶颈 = 8 轮 `score`**，占单次 auto 的 **≈68%**（其中 N1+N3 行/列扫描 ≈37%、
   N2 2×2 ≈16%、N4 暗比例 ≈15%）；`apply_mask` 再占 ≈11%。即 **8 轮择优合计 ≈79%**
   （与 S9b 早期「择优 ≈86%」方向一致，本文进一步把择优内部拆开）。
2. **小版本（V03）瓶颈 = 结果容器 `wrap_packed`**：固定容量 `Array::make(31329, …)` +
   逐格 `Array[Module]` 对象分配，占单次 auto 的 **≈44%**（0.10ms/0.23ms）；
   此时 8 轮评分只占 ≈28%。**版本越小，「固定容器开销」占比越高**，与 S9b 归因一致但量级更尖锐。
3. **真实管线（encode + Reed–Solomon + 矩阵装配）已不是热点**：V40 合计 ≈0.27ms（≈4.6%），
   V03 合计 ≈0.01ms（≈5.5%）。
4. **理论上限 ≈ fast_qr-wasm32 同执行模型数字**（V40 ≈3.03ms、V10 ≈0.32ms、V03 ≈0.059ms）——
   它是同算法、同 wasm32 的**存在性证明**。按本文优化项叠加：
   - **V40 现实目标 ≈3.2–3.9ms**，**乐观 ≈2.4–3.0ms** → fast/ours 从当前 **0.57×** 收窄到 **≈0.8–1.25×**；
   - **V03 现实目标 ≈0.09–0.12ms**（wrap + 每次 build 固定项约束），→ fast/ours 从 **0.30×** 到 **≈0.5–0.65×**，
     **仍慢于 fast 约 1.5–2×**（小版本固定成本难摊薄）。
5. 优化优先级据此反转：**先治 wrap/容器（V03 收益最大、低风险但需评估公共 `data` 语义）**，
   **再治 score 减趟 + 掩码特化（V40 收益最大）**；表示宽度重构（`Array[Int]`→窄介质）列为
   第二阶段实验项。逐项上限见 §4，完整模型见 §5。

### 单次 auto build 成本分解（wasm-gc，moonrun 边际，单位 ms）

| 基准点 | auto 总 | 8×score | 8×apply_mask | wrap | pipe(enc+RS) | matrix | 其他\* |
|--------|--------:|--------:|-------------:|-----:|-------------:|-------:|-------:|
| V03H | 0.2275 | 0.064 (28%) | 0.015 (6.6%) | 0.1005 (44%) | 0.007 (3.1%) | 0.0055 (2.4%) | 0.0355 (15.6%) |
| V10H | 0.7733 | 0.473 (61%) | 0.074 (9.6%) | 0.140 (18%) | 0.017 (2.2%) | 0.012 (1.6%) | 0.0573 (7.4%) |
| V40H | 5.900 | 4.007 (68%) | 0.660 (11%) | 0.590 (10%) | 0.1475 (2.5%) | 0.125 (2.1%) | 0.3705 (6.3%) |

> \*「其他」= `select_capacity` + `best_encoding` + 少量未分账的 GC/宿主噪声。
> 分解自洽性：`auto − fixed`（择优增量）V40 = 5.075ms ≈ `8×apply+score − 1×apply` = 4.60ms（同量级）。

## 1. 方法与口径

### 1.1 探针命令（临时包，测毕即删）

| 命令 | 含义 |
|------|------|
| `auto <V> <N>` | 公共 API `QRBuilder::…build()`（mask=None，走 8 轮择优） |
| `fixed <V> <N>` | 公共 API 指定 mask（走 `create_fixed_qr`，无择优） |
| `pipe <V> <N>` | `data_encoding.encode` + `reedsolomon.structure` |
| `matrix <V> <N>` | `create_matrix` + `place_on_matrix_data` + `create_matrix_format_info` |
| `wrap <V> <N>` | 复刻 `wrap_packed`：`Array::make(31329, Module)` + 逐格 `Module::new` |
| `mask8 <V> <N>` | 一次 `base` 上跑 8× `apply_mask` |
| `inner8 <V> <N>` | `create_auto_qr` 的内循环本体：8×(`apply_mask` + `score`) |
| `sdark / ssq <V> <N>` | 8× `score_dark` / 8× `score_squares`（score 的 4 趟之一） |

### 1.2 计时口径

- **边际斜率法**：对同一命令跑 `N` 与 `N/2` 两次整程，取 `(t(N)−t(N/2))/(N/2)`，
  消掉 `moonrun` 进程启动与运行时初始化（对齐 S9「宿主多次取最小」的思路，但更彻底地剔除固定项）。
- 每档 `R=5` 取最小，避开调度抖动；所有循环**消费结果**（累积并回写矩阵）防死代码消除。
- 与 S9j（Node 进程内单次 B 口径）互证：V03 `0.2075→0.2275`、V10 `0.729→0.773`、
  V40 `5.33→5.90`，**偏差 ≈6–11%**（宿主/harness 差异），趋势与结论一致。
- 绝对值绑定本环境；跨环境只比同 run 内的成对比值（S9h 结论）。

## 2. 实测成本分解

### 2.1 主表（单位 ms，单次 build 边际）

| 组件 | V03H | V10H | V40H | 随版本增长 |
|------|-----:|-----:|-----:|-----------|
| 编码 + RS（`pipe`） | 0.0070 | 0.0170 | 0.1475 | 线性（∝ 码字数） |
| 矩阵装配（`matrix`） | 0.0055 | 0.0120 | 0.1250 | ∝ size² 放置 |
| `wrap_packed` | 0.1005 | 0.1400 | 0.5900 | 容器固定 + 逐格对象 |
| 8× `apply_mask` | 0.0150 | 0.0740 | 0.6600 | ∝ 8·size² |
| 8× `score`（合计） | 0.0640 | 0.4727 | 4.0070 | ∝ 8·size² |
| ├ N1+N3 行/列 | 0.0600 | 0.3087 | 2.1940 | 行闭包 + 列跳访 |
| ├ N2 2×2（`ssq`） | ≈0.000 | 0.0920 | 0.9530 | 行对滑窗 |
| └ N4 暗比例（`sdark`） | 0.0040 | 0.0720 | 0.8600 | 全矩阵计数 |
| **`auto` 合计** | **0.2275** | **0.7733** | **5.9000** | — |

### 2.2 结构观察

- **score 内部三块大致三分天下再偏向 N1/N3**：V40 中 N1+N3 占 score 的 55%、
  N2 占 24%、N4 占 21%。**减趟的两块（N2/N4）合计 45%**，是最大的低垂果实。
- **`apply_mask` 与 `score` 的比值 ≈1:6**：8 轮掩码约 0.66ms（V40），
  说明 S9b 否决「就地翻转免 copy」是对的——copy 不是主项，逐格判定+扫描才是。
- **`wrap_packed` 与版本弱相关**：V03 0.1005 / V10 0.140 / V40 0.590。
  固定部分（`Array::make(31329)`，与版本无关）≈0.09–0.11ms 恒定；增长部分来自
  **逐格 `Module::new` 对象分配**（见 §3.3 实证）。

## 3. 代码级瓶颈定位

### 3.1 `score`：4 趟扫描 + 每行/列闭包 + 列跳访（`lib/internal/matrix/score.mbt`）

`score`（`score.mbt:186`）每轮调用：
```
line_rows(m,size)   // N1 运行 + N3 图案：逐行，行内调 line_score(fn(i){m[base+i]})
line_cols(m,size)   // 同上逐列，line_score(fn(i){m[i*size+col]}) —— 列内存跳访
score_dark(m,size)  // 全矩阵再扫一遍数暗块
score_squares(...)  // 行对滑窗再扫一遍
```
- **闭包税**：`line_rows`/`line_cols` 每行/列构造一个闭包并逐格**间接调用**
  （`score.mbt:87`、`:102`），V40 一轮 2×177 个闭包、每格一次间接调用；
  32 趟扫描下这是可观常数开销（对照 fast_qr 用行切片引用 + 内联，无闭包）。
- **4 趟各读一遍 125KB（V40）**，8 轮 = 4MB/次 build。但实测 4.0ms 远超同数据量 memcpy，
  说明瓶颈在**逐格计算/分派**而非纯带宽。
- **N4 暗计数**（`score.mbt:170`）与 **N2 2×2**（`:140`）各是独立整趟，
  逻辑上可与 N1/N3 行趟合并而**不改变任何分值**（§4 K1）。

### 3.2 `apply_mask`：每格 `match` 8 分支 + 整矩阵 `copy`（`lib/internal/matrix/datamasking.mbt`）

- `apply_mask`（`datamasking.mbt:38`）先 `m.copy()` 再逐格 `mask_at(x,y,idx)`
  （`:22`，含 8 路 `match`），V40 一轮 31329 格、8 轮 ≈25 万次分支分派 + 8 次整矩阵 copy。
- 掩码公式含 `%3`、`x*y%2` 等**整数除法/取模**（wasm 上较贵）；
  fast_qr 用 8 个特化函数按公式步进、无每格分派（S9b T4 已指出）。
- 实测 `apply_mask` 8 轮 0.66ms，**约占 auto 11%**；特化后有望减半（§4 K2）。

### 3.3 `wrap_packed`：固定 31329 容器 + `Array[Module]` 逐格对象（`lib/qr_build.mbt` / `lib/qr.mbt`）

`wrap_packed`（`qr_build.mbt:57`）每 build 做两件与 `size²` 无关或超线性的事：
```moon
let data = Array::make(QR_MAX_MODULES, Module::data(false))  // 恒 31329 个槽，与版本无关
while i < size*size { data[i] = Module::new(value, t) }       // 逐格构造 Module 对象
```
- **固定 31329 槽**：V03 只需 841 格（浪费 37×），实测恒定 ≈0.09–0.11ms
  —— 小版本单次 auto 仅 0.23ms，**这一项就吃掉 ≈44%**。
- **`Module` 逐格对象**：`Module` 是含 `Byte` 的 `struct`，`Array[Module]` 在 wasm-gc 下
  逐元素分配托管家对象。实测对照（同 `size²` 填格）：

  | 填 `size²` 格 | V03H | V10H | V40H |
  |--------------|-----:|-----:|-----:|
  | `Array[Int]` 写整数 | 0.0025 | 0.0080 | 0.0400 |
  | `Array[Module]` 逐格构造 | 0.0070 | 0.0270 | 0.4000 |

  → V40 下 **`Array[Module]` 比 `Array[Int]` 贵 ≈10×**（0.40ms），
  正是「固定容器 0.59ms」的大头。**注意**：S9b 的 T5 只把此项归因为「小版本浪费」，
  本文实测表明它对 **V40 同样是 10% 级**成本。

### 3.4 真实管线（`pipe`+`matrix`）已非热点

encode+RS+放置+Format 在 V40 合计 ≈0.27ms（4.6%），V03 ≈0.01ms（5.5%）。
与 S9b「非择优管线相对紧凑、优化收益远低于择优主循环」一致；
**本文新增结论**：小版本另有 `wrap` 这个与择优无关的大头。

## 4. 优化项与单项上限

> 所有项**不得改变输出明暗/元数据/择优结果**；单项收益为按本文实测成本的估算区间（非承诺）。

| 编号 | 项 | 做法（对照实码） | V40Δ 估算 | V03Δ 估算 | 风险/影响面 |
|------|----|-----------------|----------:|----------:|------------|
| **K1** | score 融合减趟 | N4 暗计数并入行趟（顺带 `dark += v&1`）；N2 2×2 与行趟按行对融合；可行时用**每列状态数组**把行/列合并为单趟（消除 `line_cols` 跳访） | **−2.5~3.5ms**（score 4.0→1.5~2.2） | −0.03~0.05ms | 中：评分对齐敏感，须快照逐位 diff |
| **K2** | 掩码判定特化 | 仿 fast_qr 8 特化函数 / 把 `match mask_idx` 提升到轮级；`%3`、`x*y%2` 用强度削减或预计算行模式 | **−0.25~0.35ms** | −0.006ms | 低：只改 `apply_mask`/`mask_at` |
| **K3** | wrap/容器 | ① `wrap_packed` 只分配 `size²`；② 内部保留 packed 字节、`QRCode.data` 改窄介质或在构造期避免逐格对象 | **−0.50~0.56ms** | **−0.09~0.10ms** | 中：`QRCode.data` 是 `pub(all)` 字段，须评估容器语义/渲染依赖（S9b T5/O3 同） |
| **K4** | line_score 闭包消除 | `line_rows`/`line_cols` 改为直接索引的行/列扫描，去掉每行闭包与间接调用（或内联取数） | 含在 K1 内，或单独 −0.3~0.8ms | −0.01ms | 低：`score.mbt` 局部 |
| **K5** | 表示宽度实验 | `internal/matrix` 工作矩阵 `Array[Int]`→`Array[Byte]`/位打包；先 `/tmp` 微基准验证再定 | 不确定，环比 −5~15% | 不确定 | 高：改面大、白盒断言多（S9b T6 同） |

> **收益重叠提示**：K1 与 K4 作用于同一批扫描，收益不可简单相加；K1 是主项，K4 是其实现手段。
> 组合估算见 §5。

## 5. 理论上限模型

### 5.1 下界：不可约的算法工作

一次 `auto build` 必须完成（保语义前提下）：模式选择 + 编码 + RS 纠错交织 +
功能图案 + 之字形放置 + Format + **8 轮掩码并逐轮按 ISO N1–N4 评分** + 输出容器。
其中 **8 轮择优是不可省的质量成本**（S9d 已论证：固定 mask0 会放弃最坏情况鲁棒性），
故「8 轮 × 全矩阵处理」是硬下界。

### 5.2 经验上界：fast_qr-wasm32（同执行模型的存在性证明）

fast_qr 用**同一算法、同一 wasm32 执行模型**跑出：

| 点 | fast_qr-wasm32（S9j） | 本仓库当前（S9j B） | 当前 fast/ours |
|----|----------------------:|--------------------:|---------------:|
| V03H | 0.059 ms | 0.198 ms | 0.30× |
| V10H | 0.323 ms | 0.729 ms | 0.44× |
| V40H | 3.021 ms | 5.329 ms | 0.57× |

→ **fast_qr 的数字就是「同语言难度量级的可实现上界」**：它证明 wasm32 上完成
「8 轮择优 + 完整 QR」可以做到 V40 ≈3.0ms。本仓库不可能突破该执行模型的物理约束太多，
但**理论上可逼近甚至局部超越**（若 pass 融合比 fast 更彻底）。

### 5.3 组合模型（按本文实测叠加，单位 ms）

| 场景 | V03H | V10H | V40H | V40 fast/ours |
|------|-----:|-----:|-----:|--------------:|
| 现状（实测） | 0.2275 | 0.773 | 5.900 | 0.51–0.57× |
| + K3（wrap/容器） | ≈0.13 | ≈0.63 | ≈5.35 | ≈0.56× |
| + K2（掩码特化） | ≈0.12 | ≈0.60 | ≈5.05 | ≈0.60× |
| + K1/K4（score 减趟，现实） | **≈0.10** | **≈0.45** | **≈3.2–3.9** | **≈0.78–0.94×** |
| + K5（介质重构，乐观） | ≈0.09 | ≈0.40 | **≈2.4–3.0** | **≈1.0–1.25×** |
| **fast_qr-wasm32（参照上界）** | **0.059** | **0.323** | **3.021** | **1.0×** |

**读数**：
- **V40 的理论可达区间 ≈2.4–3.9ms**，即**有机会追平 fast_qr（≈3.0ms）**；
- **V03 的现实上界 ≈0.09–0.12ms，仍慢于 fast 约 1.5–2×**——小版本把
  「每 build 固定项」（RS 表、容量选择、8 轮即使矩阵很小也有的调度/分配开销）摊到 841 格上，
  这部分难以进一步压缩；**不应把「V03 追平 fast」设为目标**。
- 结论与 S9b「明确不追平每模块 0.07–0.10µs」并不矛盾：S9b 是在**不改介质/容器**前提下的判断；
  本文指出**改了容器与 pass 结构后，V40 追平是可能的，而 V03 因固定成本仍会落后**。

### 5.4 不确定项（须实测再定）

- K5「窄介质」在 wasm-gc 上是否真的更快：`Byte` 运算常需掩码回 `Int`，
  收益可能被抵消——**必须先做 `/tmp` 微基准**（S9b T6 同一保留）。
- K1「行/列合并单趟」的列状态数组本身有维护成本，是否净赚取决于实现；
  建议先做**「N4 并入行趟 + N2 并入行趟」的低风险两减趟**，再评估行列合并。
- `wrap` 若动 `QRCode.data` 类型属公共 API 变更，收益/破坏性需权衡（§6 P0）。

## 6. 建议落地顺序与验收

> **优先级修订注记（2026-09-11）**：本文写作时掩码特化（K2）按保守估算排在 P1。
> 其后 [S9l](./S9l-参考fast_qr高性能实现分析.md) 的受控实验实测掩码特化 **4–5.8×**
> （V40 可省 ≈0.55ms，大于本节估算），落地顺序据实修订为
> **P0 掩码特化 → P1 容器 → P2 评分结构**，见 [S9l §4](./S9l-参考fast_qr高性能实现分析.md)；
> 本节 P0/P1 编号保留为历史评估原貌，以 S9l 为准。

### P0 — wrap/容器（小版本收益最大，先评估接口）

- 先做**不改公共字段**的一步：`wrap_packed` 内部按 `size²` 分配工作缓冲，
  再铺入 `QRCode.data`（整表 31329 的公共契约暂不动）——可先吃掉「固定 31329」那 ≈0.09–0.11ms。
- 再评估 `QRCode.data` 是否可改窄介质 / 惰性物化（属 `pub(all)` 字段语义变更，需单独评审）。
- 预期：V03 auto 0.2275→≈0.13（−43%），V40 0.591→≈0.55。

### P1 — score 减趟 + 掩码特化（大版本收益最大）

- 顺序：先 **N4 并入行趟** → 再 **N2 并入行对** → 最后评估 **行/列单趟合并**；
  每步**独立提交**，以快照逐位 diff + 双后端 checksum + 层② sha256 兜底。
- 同步做 **K2 掩码特化**（`apply_mask` 无每格 `match`）。
- 预期：V40 auto 5.90→≈3.2–3.9。

### P2 — 表示宽度实验（可选）

- `/tmp` 微基准验证 `Array[Byte]` vs `Array[Int]` 在 wasm-gc 上的行扫描/掩码吞吐，
  确认正收益再决定是否重构 `internal/matrix`。

### 统一验收（沿用 S9b §5 / S9c 同一把尺子）

1. 快照逐位 diff 零差异（择优 mask 不变）；
2. `moon fmt --check` / `moon check --deny-warn` / `moon test` 109 全绿（**仅 `wasm-gc`**；`wasm`(WASI) 已移除）；

## 8. 复现方法（探针未入库）

临时探针须放在 `lib/` 下（`lib/internal/*` 受 **internal 可见性规则**保护，
只有 `lib/` 子树可 import，故不能放 `cmd/`）。最小步骤：

```bash
# 1) 建 lib/probe/moon.pkg（executable，import lib + internal/{data_encoding,reedsolomon,matrix}）
# 2) lib/probe/main.mbt 实现 §1.1 各命令（差分/消费/防死代码消除同 cmd/bench）
export PATH="$HOME/.moon/bin:$PATH"
moon build lib/probe --target wasm-gc --release
P=_build/wasm-gc/release/build/lib/probe/probe.wasm
# 3) 边际斜率：对每命令跑 N 与 N/2 各 R 次取最小，marginal=(t(N)-t(N/2))/(N-N/2)
moonrun "$P" inner8 V40 60    # 例：8×(apply_mask+score)
moonrun "$P" sdark  V40 300   # 例：8×score_dark
```

> 注意：计时须用 **bash**（`TIMEFORMAT='%R'` + `time`）；在 zsh 下 `time` 不读该变量。
