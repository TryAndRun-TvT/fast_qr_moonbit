# src/ 核心编码管线

> **状态**：现行　｜　日期：2026-09-14　｜　索引：[docs/README-导航与索引.md](../../README-导航与索引.md) §7

fast_qr 的核心：从输入字节流到可用 QRCode 矩阵的全部计算，约 3280 行，零第三方依赖。

## 结构

```
src/
├── lib.rs           # crate 入口：模块声明、公开导出、文档示例
├── qr.rs            # QRCode / QRBuilder / QRCodeError（API 组装层）
├── encode.rs        # 三模式编码器 + best_encoding 自动探测
├── compact.rs       # CompactQR 比特缓冲区
├── polynomials.rs   # GF(256) 除法 + structure 分块交织
├── hardcode.rs      # 常量表：分组/格式信息/容量/生成多项式
├── version.rs       # Version 枚举 + const fn 容量选择 + 矩阵元数据
├── ecl.rs           # ECL 枚举（L/M/Q/H）
├── module.rs        # Module 单字节打包
├── default.rs       # 空矩阵功能图案绘制（6 类）
├── placement.rs     # 数据放置 + 掩码择优 + create_matrix 总装
├── datamasking.rs   # 8 种掩码实现
├── score.rs         # 4 规则评分
├── helpers.rs       # 终端字符画输出
└── tests/           # 11 个测试模块（黄金数据为主）
```

## 关键文件

| 文件 | 目的 |
|------|------|
| `qr.rs` | 对外 API 唯一入口；`QRCode::new` 串起整条管线（qr.rs:145-169） |
| `encode.rs` | 模式探测（Numeric→Alnum→Byte 逐级回退）与规范 8.4 节编码 |
| `version.rs` | 819 行 const fn 嵌套 match：40 版本 x 4 级别 x 3 模式的容量表；另有 `missing_bits`/`max_bytes`/`information`/`alignment_patterns_grid`/`size` 等矩阵元数据方法 |
| `hardcode.rs` | `ecc_to_groups` 的 u32 位打包技巧（`(count << 24) \| (size << 16) \| ...`） |
| `placement.rs` | 总装函数 `create_matrix`（placement.rs:122）：encode → structure → place → 择优 |
| `default.rs` | `create_matrix`（空矩阵）+ 6 个图案绘制函数；format 信息区先填占位便于后续放置 |

## 依赖

**本模块依赖**:
- `core`/`std`（仅基础类型；wasm 目标下避免 `std::error::Error` 的开销点已在 qr.rs:114 注明）

**依赖本模块的**:
- `src/convert/` — 消费 QRCode 矩阵
- `src/wasm.rs` — 消费 QRCode 与 convert

## 规范

### 代码模式

**查表优先**：任何可静态确定的数值（容量、分组、格式信息、GF 表）一律编译期常量，运行时纯查表。

**单向依赖**：`encode → compact → polynomials → placement → qr`，禁止反向引用。

### 错误处理

- 对外仅两种错误：`QRCodeError::EncodedData`（超容量）、`QRCodeError::SpecifiedVersion`
- 模式违规（如 Alphanumeric 遇非法字符）直接 panic，因为 `best_encoding` 已保证不会触发

### 测试

- 黄金数据风格：直接断言期望值表，避免"实现测实现"
- `#[cfg(test)]` 包装函数暴露私有函数（如 `test_score_line`、`test_place_on_matrix_data`）
- debug 断言做不变量检查（如 placement.rs:66-70 的位计数校验、compact.rs:216 的 8 对齐断言）

## 添加新文件

1. 在 `lib.rs` 声明模块并遵循 `#![deny(unsafe_code)]` `#![warn(missing_docs)]`
2. 依赖方向必须与现有管线一致
3. 在 `src/tests/` 增加对应测试模块并在 `tests/mod.rs` 声明
