## 3. 源码核对：2 处需修正 + 3 张旁路表补充

> 逐文件核对 `/tmp/fast_qr/src/{version,hardcode,polynomials}.rs`，对照 [S2 方案] §3 的交付描述。

### 3.1 【修正】capacity 的真正形态是 `Version::get`（最小版本选择），不是「反查容量」
- **方案 §3.1 描述**：`capacity(version, mode, ecl) -> Int`「按 (版本, 模式, ECL) 返回容量比特/字节」。
- **源码实际**（`version.rs:96` `Version::get(mode, ecl, len)`）：按 3 模式 × 4 ECL 展开为**长度分段
  阈值 → 返回最小可用版本**（如 Numeric-L：`0..=41 => V01`、`42..=77 => V02`…），共 480 段判断。
- **对 S3 encode 的意义**：encode 自动选版本用的是 `Version::get(mode,ecl,len)`——给输入长度找
  最小版本。故 capacity.mbt 必须落**「(模式,ECL,len) → 版本号」的分段阈值表**，而不是反查表。
  建议以「40 版本 × 4 ECL × 3 模式的单版本容量上限表」存储，`get` 做线性/二分查最小可用版本
  （等价于展开源码的 480 段判断，量级相同）。
- **可合并交付**：`max_bytes`（40 一维）实为「容量表中 ECL 无关的数据总字节上限」，与 `Version::get`
  的 Byte 模式一列数据同源但**语义不同**（`max_bytes` = 总数据字节上限，供 `from_version` 定缓冲）。

### 3.2 【修正】`get_polynomial` 入参是 `(version, ecl)`，返回 31 条之一
- **方案 §3.2/3.3 描述**：`get_polynomial(ec_index)`（按纠错码字数索引）。
- **源码实际**（`hardcode.rs:324`）：`get_polynomial(version, ecl) -> &'static [u8]`，在 **31 条
  生成多项式**里按 `(version, ecl)` match 选出 1 条（如 `(V01,L)=&[0,87,229,…,21]`、度 7）。
  31 条 = 度 0..30；黄金常量在 `tests/polynomials.rs::GENERATOR_POLYNOMIALS: [&[u8];31]`
  （index = 长度 - 1）。
- **实现建议**：hardcode.mbt 存两张表——`GENERATOR_POLYNOMIALS[31]`（31 条生成多项式字面量）+ 
  `polynomial_index_for[(version,ecl)] -> 0..30`（160 项选择索引），对外暴露
  `get_polynomial(version_idx, ecl_idx) -> Array[Byte]`（等价源码语义）。绝不可只按 ec_index 建表。

### 3.3 【补充】3 张旁路表：`data_codewords` / `data_bits` / `cci_bits`
方案未点名，但 **reedsolomon 的 structure 与 encode 都必需**，应一并纳入 S2 表集合：
| 函数 | 源码位置 | 语义 | S2 谁用 |
|------|---------|------|---------|
| `data_codewords(version,ecl)` | `hardcode.rs:263`（4×40 表）| 数据码字数（纠错区起点 `start_error_idx`）| reedsolomon `structure` 必须 |
| `data_bits(version,ecl)` | `hardcode.rs:297` | = `data_codewords*8` | encode 容量判定 |
| `cci_bits(version,mode)` | `hardcode.rs:302` | 字符计数指示符位数（随版本档变化）| encode 段头（S3）|
> 归属建议：`data_codewords`/`data_bits` 与容量强相关 → `capacity.mbt`；
> `cci_bits` 属编码信息 → 可放 `capacity.mbt`（与 mode 序号相关）或留 S3 encode 时再落。
> reedsolomon 只依赖 `data_codewords` + `get_polynomial` + `ecc_to_groups`。

## 5. 实现前置与收尾（评估确认）
1. **装工具链**：本会话无 `moon` → 先 `scripts/setup-moonbit.sh`（含 PATH 导出），才能 `moon check/test`。
2. **表数据 + 黄金生成**：无 cargo/rustc，不能用 Rust 编译跑出黄金；但黄金本就以**源码文本常量**
   存在于 `/tmp/fast_qr/src/tests/*.rs`（version 3876 / polynomials 1168 / structure 489 行），
   写**文本提取脚本**（sed/awk 或 node）把常量字面量转成 MoonBit 数组即可，不依赖 Rust 运行时。
3. **收尾门禁**（沿用 AGENTS §二.4）：
   ```bash
   moon fmt && moon info && moon check --deny-warn && moon test
   for t in wasm-gc wasm js; do moon build lib --target $t --release; moon test --target $t; done
   ```
4. **提交切分**（每批一个 commit，`feat(qr): 迁移 <模块>（参照 <Rust 文件>）`）：
   capacity（表+黄金）→ hardcode（表+黄金）→ reedsolomon（division→structure）→ `from_version` 回填。
