## 2.1 T5-b「不下降」门禁（v5 新增）

`bash scripts/coverage.sh --floor` 会把 `lib/**` 未覆盖行数与本文顶部
`<!-- coverage-floor: lib_uncovered=N -->` 比较，**超过即失败**。

为什么是「不下降」而不是「覆盖率 ≥ X%」：

- 行覆盖率是 **T4 变异检测的补充**；100% 行覆盖下仍可能全是 `actual == actual`（§5 铁律 3）。
- 绝对百分比阈值会诱发「为数字造无信息量用例」，直接违反铁律 6（**真值集合而非用例数**）。
- 「不下降」是可机械判定、且**只在净增未覆盖代码时才红**——这正是它要拦的东西。

处置约定：新增代码拉高未覆盖行时，要么补测（优先负向/契约用例），要么在报告里写明理由
并更新 `coverage-floor` 标记；**两条路都必须让评审看到**。

## 3. 剩余未覆盖（解读与处置）

剩余 `lib/**` 未覆盖行集中在两类**非错误路径**：

1. **防御性分支**（越界夹取、`_ =>` 兜底）——由「契约断言」而非「覆盖率」保证，
   如 `capacity.mbt` 的越界回退、`datamasking.mbt` 的 5–7 号步长特化之外的路径。
2. **`cmd/*` 探针包**（35+3+5 行）——演示/审计用途，不在分发面。

**处置结论**：不再为「覆盖率数字」造无信息量的用例（S10 §5 铁律 6：真值集合而非用例数）；
后续若新增模块，按 §5 铁律 5「负向优先」先补变异对照，再谈覆盖率。
