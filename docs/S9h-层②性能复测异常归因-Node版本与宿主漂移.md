## 0. 一句话结论

- **语义零异常**：本环境 8 组独立 run，三基准点逐位对齐 sha256 **全部**与 S9c/S9e 文档逐字相同
  （V03H `4942f6aa…b477` / V10H `91c85c94…0d8d` / V40H `c3c04930…cde7`）；体积复测与 S9g 表
  **字节级一致**（见 §6）。产物与算法无任何回归。
- **计时内部可复现**：同环境 6 组串行 run（R=5 取最小）单次值相对漂移 **≤3.8%**（比值 ≤5%），
  与 S9c 复测经验一致——测量方法本身没有噪声问题。
- **异常一：Node 大版本（受控 A/B 实验证实）**。同一台机、同一份产物、交错运行 node v22.23.1 与
  v24.20.0：**两侧在 v24 下都更快，但 MoonBit wasm 侧受益远大于 fast_qr 侧**
  （单次 B 口径 moon **−41%/−29%/−18%** vs fast **−14%/−11%/−8%**，V03H/V10H/V40H）。
  → 比值口径被 Node 版本系统性移动：V03H fast/moon(B) **0.166×（v22）→ 0.242×（v24）**。
- **异常二：宿主/会话漂移**。同为 node v24.20.0，本次宿主比 S9e 测量宿主（2026-09-10）整体快
  **23–40%**（moon B −33/−31/−23%，fast −40/−29/−20%）→ **绝对毫秒数不可跨宿主横比**。
- **稳健结论不变**：在所有测过的环境里「fast_qr 更快」的方向与量级成立（B 口径 fast_qr 快
  **2.6–6.0×**）；V10H/V40H 比值在同 Node 大版本下跨宿主稳定（±4%），**V03H 比值最敏感**
  （跨 Node 版本 ±31%、跨宿主 ±10%）。
- **规范修订**：性能数字引用必须给「**Node 版本 + 宿主 + 日期**」三元组；「MoonBit 每模块成本窄带」
  的结论应限定宿主（v24 下 0.24–0.27µs 窄带成立，v22 下 V03H 被抬高至 0.42µs 呈宽带）。

## 4. 跨会话漂移分解：两因素叠加

把「本次复测 vs S9e 基线」的净偏差沿路径 **「S9e（v24，S9e 宿主）→ 本次 v24（本次宿主）→ 本次 v22」**
拆成两个环节（B 口径；两环节**相乘而非相加**：净偏差 = (1+宿主效应)×(1+Node效应)−1）：

| 点 | 净偏差（本次 v22 vs S9e v24） | 宿主/会话效应（同为 v24：S9e 宿主 → 本次宿主） | Node 版本效应（同机：本次 v24 → v22） |
|----|-------------------------------|------------------------------------------------|----------------------------------------|
| V03H moon | **+12.8%**（0.314→0.355） | −33.0%（0.314→0.211） | **+68.5%**（0.211→0.355） |
| V10H moon | −3.4%（1.257→1.215） | −31.3%（1.257→0.864） | +40.6%（0.864→1.215） |
| V40H moon | −6.2%（9.66→9.06） | −23.2%（9.66→7.42） | +22.1%（7.42→9.06） |
| V03H fast | **−30.0%**（0.0845→0.0592） | −39.6%（0.0845→0.0510） | +16.1%（0.0510→0.0592） |
| V10H fast | −20.1%（0.401→0.320） | −28.7%（0.401→0.286） | +12.2%（0.286→0.320） |
| V40H fast | −14.0%（3.554→3.055） | −20.7%（3.554→2.817） | +8.4%（2.817→3.055） |
| 比值 V03H | 0.269→0.166（**−38%**） | 0.269→0.242（−10%） | 0.242→0.166（−31%） |
| 比值 V10H | 0.319→0.263（−18%） | 0.319→0.330（+3%） | 0.330→0.263（−20%） |
| 比值 V40H | 0.368→0.337（−8%） | 0.368→0.380（+3%） | 0.380→0.337（−11%） |

- **净偏差的正负号有迷惑性**：moon 侧 V03H 净看是「+12.8% 慢了」，实为 v24 受益 −33% 与
  v22 回吐 +68.5% 两环节相抵——**单看净偏差会把环境差误读成实现回退/进步**，必须分解。
- **宿主效应单独就有 ±20–40%**（两侧都有、方向同侧）——与 S9c「并行污染抬升 ~40%」同量级，
  但这次是**环境本身**而非负载。跨会话引用绝对值没有意义。
- **比值在同 Node 大版本下相对稳**：V10H/V40H 仅 ±4% 内（0.319→0.330、0.368→0.380），
  V03H −10%（0.269→0.242）。**比值跨 Node 大版本则大幅移动**（V03H ±31%）。
- S9e「量级结论」（fast_qr 快 2.7–5.7×）在全部三个环境组合中都成立：
  本次 v22 为 **3.0–6.0×**、本次 v24 为 **2.6–4.1×**（B 口径）——方向稳健、倍率随环境浮动。

## 5. 详细分析与规范修订

### 5.1 为什么 MoonBit 侧对 Node 版本敏感得多（方向性解读）

- 两侧产物形态不同：MoonBit 侧是**自包含 WASI 可执行包**（`_start` + 自管线性内存运行时 +
  externref argv 协议），fast_qr 侧是 **wasm-bindgen 库导出**（胶水承担调用面）。
  MoonBit 侧「每次 build」的执行几乎全在 wasm 线性内存上跑自管运行时代码，
  对 V8 wasm 管线的优化特征（内联/边界检查消除/GC 辅助路径）更敏感；fast_qr 热路径更「朴素」，
  两个 V8 版本下都跑得接近其 LLVM 生成代码的下限。
- 版本越小效应越大：小版本单次时长短，**宿主固定项占比高**（S9e 已测 Instance 创建 ≈83µs/次，
  V03H 上占比 ~17%），引擎升级对固定项与热点代码**双重**改善被放大。

### 5.2 「每模块窄带」结论需限定宿主（对 S9c §3.2 的修订）

| 宿主 | MoonBit µs/module（V03H/V10H/V40H，B 口径） | 形态 |
|------|---------------------------------------------|------|
| node v24（本次） | 0.250 / 0.266 / 0.237 | **窄带**（±6%） |
| node v22（本次） | 0.422 / 0.374 / 0.289 | **宽带**（V03H 被抬高 +46%，相对 V40H 档） |
| moonrun（S9c 时代） | 0.362 / 0.358 / 0.287 | 准窄带 |

- S9c「每模块成本稳定在窄带 ⇒ 纯常数系数特征」的解读**在 v24/moonrun 下成立**；
  在 v22 下小版本被宿主固定项抬高，窄带消失。**引用该结论时必须带上宿主**。

### 5.3 引用规范（本次修订的核心产出）

1. **三元组原则**：引用任何层②数字必须同时给「Node 版本 + 宿主/日期 + 口径（A/B）」，
   缺一即不可比。文档示例：`V40H 单次(B) 9.66ms @ node v24.20.0 / 2026-09-10 宿主（S9e）`。
2. **跨环境只比比值，且分级**：V10H/V40H 比值跨宿主稳（±4%）、跨 Node 大版本移 ~±15%；
   V03H 比值两者都敏感（±10% / ±31%）——**V03H 比值只作同环境内的相对参照**。
3. **复现路径钉版本**：复现 S9e 表需 node **v24.20.0**；在别的 Node 上请以本文件 §3.2 为参照系，
   而不是拿数字直接对撞。
4. **正确性口径不受影响**：逐位对齐 sha256 与 checksum 与宿主/版本无关，任何时候都应零差异
   （本次 8 组 run 全部 ✅）。

### 5.4 对 S9b 优化基线的影响

- S9b/S9e 以「V40H 边际 ~9ms、fast 3.18–3.55ms」为优化前后同一把尺子。本次复测表明：
  **该尺子依然有效，但必须「同环境成对复跑」**——优化前后在同一台机、同一 Node 上各跑一次
  `bench-layer2.sh`，比值变化才可归因于代码改动（本次已证明环境本身可移动 ±20–40%）。
- 顺带的好消息：在 node v24 上，MoonBit 侧基线本身比旧记录快 18–41%（V40H B 口径 7.42ms），
  与 fast_qr 的差距比旧表更小（2.6× 而非 2.7–3.7×）。S9b 验收时建议**同时记录 v22/v24 双值**
  或钉死一个版本。

## 8. 汇总

1. **异常定位**：复测与 S9e 基线的偏差不是噪声（同环境 ≤3%），是两个受控确认的环境因素——
   **Node 大版本**（moon 侧 −18~41%、fast 侧 −8~14%）+ **宿主/会话**（两侧再 ±20–40%）。
2. **语义零回归**：8 组 run 逐位对齐 sha256 与文档逐字一致；体积复测字节级复现 S9g。
3. **结论稳健性分级**：方向性结论（fast_qr 更快 2.6–6.0×）全环境成立；
   V10H/V40H 比值同 Node 大版本下稳（±4%）；V03H 绝对值与比值均环境敏感。
4. **规范**：性能数字绑定「Node 版本 + 宿主 + 日期」三元组；跨环境只比同 run 成对比值；
   复现 S9e 钉 node v24.20.0；S9b 优化验收须同环境成对复跑。
5. **修订落点**：S9e 记录加修订注记；README 性能速览加环境警示与本文链接；
   `bench-layer2.sh` 头注释补 Node 版本警示。
