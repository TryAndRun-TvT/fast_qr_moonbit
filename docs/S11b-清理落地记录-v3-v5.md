## 12. v4：**文件级**「无实践内容」盘点与移除（2026-09-14，实跑）

> 本节响应 Issue #63 第四轮：「`fast_qr_moonbit.mbt` 等**无实践内容**的文件，思考并评估如何移除」。
>
> §2 的 v1/v2/v3 一律在**符号级**找冗余（`pub fn` 有没有生产调用）。本节换一把尺子：
> **文件级**——一个 `.mbt` 若**没有可执行内容**（纯注释），或**全部内容都是别处可容纳的薄委托**，
> 它就是一个「无实践内容」的载体，应当**合并/删除**而不是「留着当文档」。
>
> **方法**：任何一条文件级删除，都先用「**删除文件 + `moon check --deny-warn` + `moon test`
> + `moon info` 对比 `.mbti`**」四步实证其零影响，再决定。
>
> 全程门禁（实跑）：`fmt --check` / `check --deny-warn` / `moon test` **146**（default + wasm-gc）/
> `wasm-gc` release 构建 / `test-scale` / `docs-link-check` **487 链零死链** /
> `coverage --floor` **15 ≤ 15** / 变异检测 **21/21 全检出**。

### 12.1 判定口径：什么叫「无实践内容的文件」

| 类别 | 定义 | 判定命令 | 处置 |
|:----:|------|---------|------|
| **F1 纯文档头** | 文件**零可执行语句**（只有 `///` 注释 + `///|` 分隔符），对外部无任何贡献 | `grep -vE '^\s*(///\|?//?\|?$)' <f>` 为空 | **删**（内容并入职责文档/README 索引） |
| **F2 薄委托文件** | 文件全部内容 = 1–2 个「转发调用」的 `pub` 方法，可直接并进被委托函数所在文件 | 行数 ≲ 25 且每个函数体 ≤ 1 行 | **合并**（就近放置），不改 API |
| **F3 零生产引用符号** | 符号无任何非测试调用方（§2.4 口径） | `grep` 排除 `*_test.mbt`/`*_wbtest.mbt` | **删**（测试同步改等价写法） |

> **与 v1/v2/v3 的区别**：前几轮只做 F3（符号级）。**F1/F2 是「无实践内容」的另一种形态**——
> 符号都在、编译也过，但**载体本身没有实践内容**：`fast_qr_moonbit.mbt` 是「注释即文件」，
> `qr_output.mbt` 是「2 行转发即文件」。这类文件在 `moon check --deny-warn` / 覆盖率 / 变异检测
> **全部看不见**（它们既不产生未覆盖行，也没有可植入的缺陷），只能靠**文件级尺子**发现。

### 12.2 实测盘点（本节新增口径：文件级）

复跑命令：

```bash
# ① F1：找出「去掉注释后为空」的 .mbt（pkg.generated.mbti 是构建产物，不管）
for f in $(git ls-files '*.mbt'); do
  n=$(grep -vE '^\s*///' "$f" | grep -vE '^\s*$' | grep -vE '^\s*///\|' | wc -l)
  [ "$n" -eq 0 ] && echo "F1 纯文档头: $f"
done

# ② F2：找「代码行极少」的 .mbt（<25 行非注释），再人工判是否薄委托
git ls-files '*.mbt' | while read -r f; do
  n=$(grep -vE '^\s*///' "$f" | grep -vE '^\s*$' | wc -l); echo "$n $f"
done | sort -n | head
```

实测结果（`main@652adfe`）：

|------|:-----------:|:----:|------|------|

| `lib/qr_output.mbt` | **6** | F2 | 仅 `QRCode::to_str`/`print`，各 1 行转发 `helpers.mbt` | **合并进 `helpers.mbt`** |

### 12.3 逐项分析与实证

#### (1) `lib/fast_qr_moonbit.mbt` —— F1 纯文档头（**已删**）

- **它是什么**：17 行 `///` 注释，0 行可执行代码。内容 = 「本包公共 API 散布在哪些文件」
  + 「历史 S1–S7 双后端」+ 一个指向 `docs/S8` 的相对链接。
- **为什么是「无实践内容」**：
  1. MoonBit **同包内所有 `.mbt` 共享命名空间**，无需任何 re-export —— 该文件**在语言层面不做任何事**；
  2. 它声称的「公共 API 总览」在 **README「公共 API 一览」与
     `docs/moonbit-实现布局与文件职责.md §3.1 文件职责表**里**各有一份更完整、更准确的版本** → 属 §5.2 **R1 跨文档复述**；
  3. 它的「历史」段落**已经陈旧**（`S1-S7`、`109 全绿`、`wasm-gc/wasm 双后端`——双后端已在 S9n 收敛为
     仅 `wasm-gc`）→ 属 §5.2 **R2 历史口径未标注**。**「陈旧注释即死文档」**，正是 S8 §0 自己点名的缺陷。
- **零影响实证（四步，实跑）**：

  ```bash
  cp lib/pkg.generated.mbti /tmp/base.mbti      # ① 取删前契约快照
  git rm lib/fast_qr_moonbit.mbt                # ② 删文件
  moon check --deny-warn   # → Finished（0 警告 0 错误）
  moon test                # → Total tests: 146, passed: 146, failed: 0
  moon info && diff /tmp/base.mbti lib/pkg.generated.mbti   # → 无输出（逐字节相同）
  ```

  → **删除前后 `.mbti` 逐字节一致**，证明该文件对公共契约**零贡献**。
- **替代承载**：README「公共 API 一览」+ `moonbit-实现布局与文件职责.md §3.1`（**均已存在**，无需新建）。

> **判定纪律**：一个「只写文档不写代码」的 `.mbt`，其唯一体面归宿是**项目文档**，
> 而不是「源码目录里的注释」。否则它必然随实现漂移，且**没有任何门禁能发现它漂移**
> （`fmt` 只管格式、`check` 不看注释、`test`/`coverage`/`mutation` 都看不见它）。
> **删除收益 = 消除一条「永不报错但必然陈旧」的文档路径。**

#### (2) `lib/qr_output.mbt` —— F2 薄委托文件（**已合并**）

- **它是什么**：21 行文件，真正的实现是 2 个方法：

  ```moonbit
  pub fn QRCode::to_str(self) -> String { print_matrix_with_margin(self) }
  pub fn QRCode::print(self) -> Unit { println(self.to_str()) }
  ```

- **为什么是「无实践内容」**：**全部实践（渲染算法）都在 `helpers.mbt`**，本文件只做转发。
  一个「只含 2 行转发」的独立文件，其**唯一信息量是「这里有 2 个方法」**，
  而这在 `.mbti` 与 README 里已经写了。
- **为什么不直接删方法**：`to_str`/`print` 是**参考 fast_qr `qr.rs:174-185` 的公开面**
  （README「公共 API 一览」已登记），删了会缩小公共 API → **只能合并、不能删除**。
- **处置**：两个方法**就近并入渲染引擎 `lib/helpers.mbt`**。收益：
  ① 少一个文件（文件数 26 → 24 见 §12.5）；
  ② `to_str` ↔ `print_matrix_with_margin` 的委托关系在**同一文件内**可见（原本跨文件）；
  ③ `.mbti` **零变化**（方法仍是 `QRCode` 上的 `pub fn`，只是换了所在文件）。
  **实证**：`moon info` 后 `to_str/print` 仍在 `.mbti`，签名不变。
- **代价**：`helpers.mbt` 从 98 → 112 行（远低于「文件过大」信号）；
  `docs/S8` 的 D11「从 qr.mbt 拆出输出便捷」决策被**部分回退**——本节在 §12.6 显式记录并给理由。

#### (3) 三个零生产引用符号（F3，**已删**）

本轮沿用 §2.4 的引用面尺子，又筛出 3 个（v3 删 8 个之后的剩余面）：

| 符号 | 引用面证据 | 判定 | 处置 |
|------|-----------|------|------|
| `QR_MAX_WIDTH`（`const = 177`） | 生产引用 0；唯一引用是**黑盒断言自己** | `QR_MAX_MODULES` 已是「边长 ≤ 177」的**单一事实源**（`177*177 == 31329`） | 删；断言改 `Version::V40.width() * Version::V40.width() == QR_MAX_MODULES` |
| `QRCode::for_version` | 生产引用 0；**与 `QRCode::empty` 完全同义**（body 就是 `QRCode::empty(v)`） | v3 P1-3 引入 `empty` 后即退化为纯别名 | 删；测试改 `empty` |
| `Module::dark(value)` | 生产引用 0；仅 1 处黑盒断言 | `Module::new(value, DarkModule)` 是唯一通用构造 | 删；断言改 `Module::new(true, DarkModule)` |

- **`QRCode::empty` 的连带简化**：原实现是 `QRCode::default(v.width()).with_version(v)`，
  其中 `with_version` 是**纯私有糖**（只有 `empty` 调用）。删 `for_version` 后，改为
  **直接构造结构体字面量** → 私有 `with_version` 一并消失（**避免「构造糖套构造糖」**）。
- **`default` 与 `empty` 并存的处理**：`QRCode::default(size)` 名义零生产引用，但它承担
  「任意 `size`」（如 7×7 受控矩阵，见 `s7_terminal_test.mbt`），**是测试真值构造所需**，
  不同于 `QR_MAX_WIDTH`（无信息重复）→ **保留**（同 §2.3 的「不删有信息量的」纪律）。
- **`Module::dark` 与 `Module::data` 的不对称**：`data` 有生产调用（`qr.mbt`/`qr_build.mbt` 的矩阵
  初始化），`dark` 无 → 只删 `dark`，保留 `data`。**不做「对称性审美删除」**（否则会破坏生产路径）。

### 12.6 与 §7 执行纪律的一致性（以及一处**显式回退**）

§7 的六条纪律本轮全部遵守（一次一主题 / 删除前三件套 / `mutation` 前确认 `lib/` 干净 /
小步提交 / 改公共面同步文档 / 不删有信息量的历史）。其中**改动公共面**的同步清单（§7-5）已执行：

- README 项目结构树：移除 `fast_qr_moonbit.mbt` / `qr_output.mbt` 两行，改注「公共 API 一览见上表」；
- `docs/moonbit-实现布局与文件职责.md` §2 布局树 + §3.1 职责表：同步删两行；
- `docs/S8-内部结构归位与分层.md`：D11 决策加「**v4 部分回退**」批注（见下）。

> **显式回退（要求评审可见）**：S8 决策 **D11** 曾把「`to_str`/`print` 便捷方法」从 `qr.mbt`
> 拆成独立 `qr_output.mbt`，理由是「子关注分离」。v4 判定其**净收益为负**：
> 拆出后 `qr_output.mbt` 只承载 2 行转发，而**渲染算法在 `helpers.mbt`** ——
> 「便捷方法」与「被委托的引擎」被拆到两个文件，反而**降低**了可导航性。
> 故 v4 **把该文件合并回 `helpers.mbt`**（D11 的「结果容器/编排/QRBuilder 三分」**保持有效**，

### 12.7 一句话总结

### 13.1 判定口径：什么叫「过期注释 / 过期口径」

| 类别 | 定义 | 例 | 处置 |
|:----:|------|----|------|
| **S1 失实状态** | 注释/文档称「骨架 / 待实现 / 无逻辑」，而实现**早已落地** | `mode.mbt`「S1 仅建骨架…随批次 B7 落地」 | **更新**为真实状态 |
| **S2 失效指向** | 引用**已删/已合并**的文件（或指错文件）为「当前」载体 | `helpers.mbt`「`print` 副作用由 qr.mbt 承担」 | **更新**指向 |
| **S3 陈旧处方** | 文档**指示**读者照做，但该做法已失效（会重建已删文件） | 目录设置 §四「库 API 写 `lib/fast_qr_moonbit.mbt`」 | **更新**（否则误导） |
