### 0. 一句话结论

S5 落 **`internal/matrix/score.mbt`**（4 条评分 N1/N2/N3/N4）+ **`internal/matrix/placement.mbt`**
新增**自动择优入口**（基础矩阵一次构建 → 8 轮 clone+mask+score → 选最低分 mask → 写真实 Format +
应用最优 mask），lib 侧新增/扩展 `QRCode::build`（mask 可 None 自动择优）串成**自动参数完整 QRCode**。
S5 唯一结构性缺口是 **N4 的 `PERCENT_SCORE` 暗模块比例表**（参考 hardcode.rs:406）尚未随 S2 落进
`constants/hardcode.mbt`——S5 需在具备 Rust 环境用脚本提取补齐（roadmap 铁律：禁止手抄大表）。
S5 **不做 60 快照全量对齐**（那是 S6/M2）；本阶段以 **score 白盒黄金 + 择优 mask 选择与参考一致**
的确定性子集验收，确保自动择优正确收敛后再交由 S6 铺开全量快照。

> 8 种掩码**数学式实现**随 S4 落（可独立快照验证）；S5 只做 **4 条评分 + 8 轮 clone+score 择优主循环**
> （B10 后半）——降低 S5 耦合、避免 S4 只写单掩码再返工补 7 种。

### 3. 关键架构决策与逐文件落地清单

#### 3.1 决策 D4：评分结果收敛为单 `Int` 总代价分，逐条规则可独立白盒
- **问题**：score.rs 将 4 条规则得分相加（总分越低越优），择优在 placement 里取最低分。
- **方案**：`score.mbt` 暴露
  - `score_row/col`（N1 行/列连续同色）、`score_squares`（N2 2×2）、`score_pattern`（N3 11 位窗口）、
    `score_dark`（N4 暗比查表）各自可独立调用（白盒黄金测每一条），
  - 汇总入口 `score(m, size) -> Int`（参考 `score.rs::score` :195，= 4 条之和）供择优主循环调用。
  - 优点：每条规则可独立以 `tests/score.rs` 黄金断言验证，避免择优整链出错时难定位；与参考
    `score.rs` 把 `line`/`col`/`pattern`/`square`/`dark` 相加的语义一致。
- **介质沿用 D3**：评分函数收发原始字节矩阵 `Array[Int]` + size，与 placement/datamasking 一致，
  不 import lib。

#### 3.2 决策 D5：择优主循环「先掩码后评分」且在已掩码副本上逐轮求值
- **铁律**（framework §五.6 / concept 不变量 2）：**列评分必须在掩码后做**（placement.rs:100-104 历史
  bug 注释）；掩码应用后评分，垂直惩罚才不会退化为常量。
- **方案**：新入口 `create_auto_qr(structure, v_idx, ecl_idx) -> (Array[Int], Int)`（返回最优矩阵 + 最优
  mask 号），算法 = 参考 `placement.rs:85-119`：
  1. `base = create_matrix(v_idx)` + `place_on_matrix_data(base, size, structure)`（**基础矩阵只建一次**，
     roadmap 决策 5：非 Data 格类型固定、明暗位随放置就位，仅 Data 区内容固定）；
  2. 对 k in 0..8：`masked_k = apply_mask(base, size, k)` → `s_k = score(masked_k, size)`；
  3. 取 `s_k` 最小者（**并列取先到的低位 k**，与参考 `cmp::min_by` 从左到右的语义核对）记 `best_mask`；
  4. 在最优 `masked_best` 上 `create_matrix_format_info(…, ecl_idx, best_mask)` 覆写真实 Format
     （时序铁律 §五.7：Format 占位先写、择优后以真实值覆写）；返回最优矩阵 + best_mask。
  - **format 覆写 vs 掩码的先后**：S4 固定 mask 是先 `create_matrix_format_info` 再 `apply_mask`
    （Format 区被固定 mask 应用后已定型、不再翻转）。但**择优路径**中 8 轮要对**同一 Format 占位**分别
    掩码评分，故 Format 真实值应放在**选中最优 mask 后**统一覆写（参考 `place_on_matrix` 的
    「循环内评分用占位、结束才写真实 Format」）。两种路径的差异需在实现时以参考 `placement.rs` 择优
    分支逐行核对锁死（见 §4）。

#### 3.3 依赖与落点切分

| 函数 | 文件 | 参考锚点 | 需 dependencies |
|------|------|---------|----------------|
| `N4` 表提取 | `constants/hardcode.mbt` | `hardcode.rs:406` | 无（constants 自洽）|
| `score_row/col/…/score` | `internal/matrix/score.mbt` | `score.rs` | module helpers（同包）|
| `create_auto_qr` | `internal/matrix/placement.mbt` | `placement.rs:85-119` | apply_mask(同包) + score(同包) + create_matrix/format_info(同包) |

- matrix/moon.pkg **无需新增 import**：score 与 placement 均在同一 `internal/matrix` 包内互调；
  constants（N4 表若放 constants 供 score 查）由 matrix/moon.pkg 既有 constants import 覆盖。
- 但 score 若要查 PERCENT_SCORE：表放 `constants/hardcode.mbt`，score 通过 `@constants.…` 访问——
  matrix/moon.pkg 已 import constants，满足。若实现时表改放 matrix 包内（见 §8 备选），则 constants 不新增
  表、score 同包引用——两条路径都不破坏无环，由实现时按「表归位一致性」（对齐 S2 hardcode 大表全集中）
  选 constants 归位。

#### 3.4 `internal/matrix/score.mbt` 各函数落地（4 条规则，逐一对应参考）
| 规则 | 函数 | 语义（framework §五.6 / concept）| 参考锚点 |
|:---:|------|------------------------------|---------|
| N1 | `score_line(m, size) -> Int`（行）| 每行自首尾各补 4 个**浅色**（quiet zone）；扫描连续同色模块，`N >= 5` 计 `N-2`；连续段被功能模块/浅色边界中断即结算 | `score.rs` `line` :82 / :84-100 quiet zone 注释 |
| N1 | `score_col(m, size) -> Int`（列）| **必须在掩码后**做；等价按列扫描（MoonBit 用转置拷贝或直接按 `row*size+col` 跳跃扫描，避免整矩阵转置）| `score.rs` 列路径（栈上缓冲避免转置）|
| N2 | `score_squares(m, size) -> Int` | 逐 2×2 块判四格同色（明暗自 `value`）；**触及功能模块不计分且连续性归零**（concept 不变量 4）| `score.rs` `matrix_score_squares` :42 / :60-64 类型门槛 |
| N3 | `score_pattern(m, size) -> Int` | 11 位滚动窗口按值比较检测类 finder 图案：`0b00001011101` 与 `0b10111010000`，每命中记 **40**；**quiet zone 行首/尾各补浅色**（双侧浅命中计两次）；需行 + 列两向 | `score.rs` `PATTERN_LIGHT_BEFORE/AFTER/WINDOW` / N3 窗口 |
| N4 | `score_dark(m, size) -> Int` | 统计暗模块数 → 占比 → 查 `PERCENT_SCORE` 表；每偏离 50% 一档（5% 步长）给固定惩罚分 | `score.rs` `dark_module_score` :178 |
| 汇总 | `score(m, size) -> Int` | = N1 行 + N1 列 + N2 + N3 + N4 | `score.rs::score` :195 |

> **N1/N3 的 quiet zone 细项**（最易错、framework 反复强调）：
> - 每行首尾**各视为 4 个浅色模块**（对应符号外安静区），供 N1 结算与 N3 窗口滑到边界时用；
> - N3 若行首/行尾双侧都是浅色补足命中窗口，会**计两次 40 分**（两侧 quiet zone 各自命中）。

#### 3.5 lib 自动择优入口（mask 可 None）
S4 `QRCode::build_fixed` 的 mask 为 `Mask`（必填）。S5 建议新增/扩展自动入口：
- `QRCode::build(input, mode, ecl, version, mask)`：`mask = Some(m)` 走 build_fixed 语义（**仍评估但用
  用户指定**，concept 不变量 6）；`mask = None` 走 `create_auto_qr` 择优、返回最优 mask 并写入元数据。
- 复用 select_capacity → encode → structure → （固定 or 择优）→ 逐格包装回公共 Module。
- 为避免黑盒 public 面过早定型，可先落内部/半公开组装函数，`QRBuilder` builder 壳随 S6。

### 5. 测试与验收

#### 5.1 前提：在具备 Rust 的环境生成 score 黄金与择优快照（复用 S4 工具链）
roadmap §4.1 / S4 §6.1 的 `examples/snapshot_gen.rs` 已验证可用。S5 需在**一次具备 Rust 环境**补两类数据：
1. **score 黄金**：从 `/fast_qr/src/tests/score.rs`（415 行）转译 N1-N4 各规则期望值 → MoonBit 白盒
   `score_wbtest.mbt` 常量（同 S2 的 structure.rs 黄金转译法）。
2. **择优快照**：扩展 snapshot_gen 或新增小工具，对若干 (content, ecl, version) 输出参考库**自动择优
   选中的 mask** + 最终矩阵，供 MoonBit 侧 `create_auto_qr` 对齐（至少覆盖 Byte 若干内容 + 各 ECL +
   低/中版本，验证 8 轮择优与并列语义）。

#### 5.2 白盒 `score_wbtest.mbt`（新文件，落 matrix 包内）
- N1 行连续：构造已知矩阵 → 断言 N1 分值（含 quiet zone 边界结算）；
- N1 列连续：掩码后矩阵 → 列分值；
- N2 2×2：同色块计 3 / 触及功能模块不计分；
- N3 窗口：类 finder 图案命中 40、quiet zone 双侧补浅命中两次；
- N4 暗比：构造已知暗比 → 查表分；
- `score` 汇总 = 四规则之和。

#### 5.3 白盒 placement 择优
- `create_auto_qr` 对已知 structure：8 轮逐一 score，断言选中的 best_mask 与手工算最低分一致；
- 并列语义：构造两个等分 mask 场景 → 断言取先到的低位；
- 功能模块明暗不变（掩码只动 Data 已由 apply_mask 保证，此处断言择优后 Format 真实值写入）。

#### 5.4 黑盒 lib 自动入口
- `QRCode::build(input, None-ecl/version/mask)` 对若干输入：断言返回 `mask` 元数据 = 参考择优 mask、
  全矩阵与参考自动二维码矩阵一致（择优子集快照对齐）。
- `mask = Some(指定)` 走固定路径语义仍绿（既有 build_fixed 测试回归）。

#### 5.5 门禁（沿用 AGENTS §二.4）
```bash
moon fmt && moon info && moon check --deny-warn && moon test   # 预期 77 → 约 85+
for t in wasm-gc wasm; do moon build lib --target $t --release; moon build cmd/main --target $t --release; moon test --target $t; done
```
- `.mbti` 护栏：score 内部函数不泄漏 lib；lib 若新增 `build` 入口属预期；matrix 包内测试用
  `*_wbtest.mbt` 白盒。
- 不得入库构建产物（`_build/`、`*.wasm`、`*.mbti` 已 gitignore）。

#### 5.6 验收 = 自动择优正确收敛
score 黄金 + 择优 mask/矩阵与参考一致 + 门禁全绿 = S5 达成；产出即 S6 全量 60 快照对齐的唯一前置。

### 2. 关键实现语义（对照参考源码核验）

- **N1/N3 共用的 `line` 逻辑**（`score.rs::line`）：运行只在 Data 上累计、非 Data/变色即结算；
  N3 11 位滚动窗口 `0b00001011101`（浅前）/`0b10111010000`（浅后），quiet zone 由窗口初值 0（行首
  4 浅色）+ 行尾补 4 浅色移位体现，**双侧浅命中各计 40**；N1 运行只算符号内（quiet zone 不参与）。
- **N2 2×2**（`matrix_score_squares`）：buffer 4 bit 窗；触及非 Data 计连续性归零、同色块各 3 分。
- **N4**（`dark_module_score`）：统计暗模块 → `percent = dark*100//(size*size)` → 查
  `constants.percent_score(percent)`。
- **列评分必须在掩码后**：择优每轮 `masked = apply_mask(base,k)` 再 `score(masked)`。
- **Format 时序**：基础矩阵含浅色占位 → 8 轮在占位上评分（类型 Format 不参与翻转/运行）→ 选中最优后
  在基础矩阵覆写真实 Format → 应用最优掩码（只动 Data）。
- **并列取低位 mask**：`score < best_score` 严格小、0..7 从左到右扫描，首遇最低分即锁。

### 2. 发现并落地（非正确性）

#### 2.1 【已修正·注释口径】固定 mask 路径注释「仍评估、但用用户的」失实

- **现象**：`qr.mbt` 中 `QRCode::build` 的两处注释（函数文档注释 + `Some(m)` 分支行注释）均写
  「`Some(m)` …（仍评估、但用用户指定的）」/「指定固定掩码：仍评估但用用户的」，暗示固定 mask 时
  MoonBit 仍会跑 8 轮评分。
- **实际行为**：`Some(m)`/`build_fixed` 走 `create_fixed_qr`（`placement.mbt`）——**不跑 8 轮评分**，
  只 `apply_mask(m, size, mask_idx)` **一次**用户 mask。
- **与参考的关系**：fast_qr `place_on_matrix` 是**无条件**跑 8 轮评分选出 `best_mask`，随后
  `best_mask = mask.unwrap_or(best_mask)` 用用户 mask **覆盖**再 apply——即参考是"照跑评分但结果用用户
  的"。两者最终矩阵**输出等价**（均以用户 mask 应用一次），因此 MoonBit 直接跳过冗余 8 轮评分属
  **合理优化、非行为差异**。
- **修复**：将两处注释改为如实表述——固定 mask 走 `create_fixed_qr` 快速路径，**直接应用用户 mask、
  跳过冗余 8 轮评分（输出等价参考强制掩码旁路）**。纯注释改动，未改逻辑，`.mbti` 不变。
- **验证**：85/85 测试、双后端回归全绿（与改动前一致）。

#### 2.2 【已修正·文档澄清】参考概念文档补 MoonBit 落地注记

- `docs/移植参考/专有概念/掩码与评分.md` 不变量 6 记录的是 **fast_qr 真实行为**（"评分循环照跑但结果
  被覆盖"），其本身**准确**、不应改写。
- 但为消除歧义（防误以为本仓库 fixed 分支也照跑评分），在不变量 6 下补一条 **MoonBit 落地注记**：本仓库
  `create_fixed_qr` 采用等价快速路径（跳过评分直接 apply），输出与参考强制掩码旁路等价。属合理优化。

#### 2.3 【参考继承·备查】auto 路径按浅占位 Format 择优

- `create_auto_qr` 先在含**浅色占位 Format** 的基础矩阵上跑 8 轮评分，选中最优 mask 后才在基础矩阵
  覆写**真实 Format**（`create_matrix_format_info`）并 apply 最优 mask。
- 与 fast_qr `place_on_matrix` 时序完全一致（参考同样在占位浅 format 上择优、后写真实格式），
  **0 差异已证**，非缺陷。浅占位以 `module_type_format` 类型标记，评分时不被当作 Data 计入运行，故不影响择优。

#### 2.4 【稳健增强·确认】`percent_score()` 越界 clamp 优于参考裸索引

- MoonBit `constants.percent_score(percent)` 对越界做 clamp：`percent<0` → 取 `[0]`、`percent>99` →
  取 `[99]`（`hardcode.mbt`）。
- 参考 fast_qr `dark_module_score` 为 `hardcode::PERCENT_SCORE[percent]` 裸索引，而
  `percent = dark*100/(n*n)` 理论最大可到 `100`（全暗），此时参考会**越界 panic**；MoonBit 的 clamp
  属**保险性增强**，不改变正常输入下的取值。确认保留。
