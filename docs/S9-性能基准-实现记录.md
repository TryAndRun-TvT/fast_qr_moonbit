## 2. 层① 实测数字（wasm-gc vs wasm，同源码跨后端选型）

命令：`moon run cmd/bench --release --target <后端> -- <点> <N>`，宿主重复 R=3 次取最小 wall time
（整程含运行时启动，剔冷启动，量级供选型/对比）。输入 `https://example.com/`（20 字节），ECL=H，
mask 自动择优（8 轮评分，对齐 fast_qr benches 默认）。

| 基准点 | 迭代 N | wasm-gc 最小 (s) | wasm 最小 (s) | 相对 (wasm/wasm-gc) | TOTAL_CHECKSUM |
|--------|-------:|----------------:|-------------:|--------------------:|---------------:|
| V03H | 2000 | 0.695 | 0.854 | 1.23× | 82000 |
| V10H | 400 | 0.451 | 0.621 | 1.38× | 32400 |
| V40H | 40 | 0.369 | 0.484 | 1.31× | 9200 |

> - **wasm-gc 全程更快**（约 1.2–1.4×），与 wasm §5.2 骨架微基准「wasm-gc 快约 33%（≈1.33×）」叙事一致，
>   印证后端选型判断；且这次是**真实 QR 生成路径**（encode→structure→放置→8 轮评分择优→build），把 wasm
>   §5.2 的独立 `/tmp` 朴素负载升级为**入库存量、可复跑**。
> - **TOTAL_CHECKSUM 跨后端逐点一致**（82000/32400/9200）：同一份源码在 wasm-gc 与 wasm 得到同一结果 →
>   层①的**结果互证**成立（各点 checksum = Σ(N 次成功的 size + 代表性模块字节 + 元数据序号)）。
> - 每点耗时已配独立迭代数使单点 ≈0.4–0.9s，远离 <1ms 计时噪声区间；单点进程整程计时含启动开销，故单次
>   build 的纯路径成本应看相对/吞吐趋势（V03 < V10 < V40 单调上升符合版本越大放置/评分越贵的直觉）。

### 2.1 单次 build 粗估（整程均摊，仅供量级）
将每点整程 wall time 均摊到 N 次（含启动摊销），得 MoonBit wasm-gc 单次量级参考：
V40H ≈ 9.2ms、V10H ≈ 1.1ms、V03H ≈ 0.35ms。参考 fast_qr **64 位 native**（criterion）为
82.2/269.3/2436.2 us（V03H/V10H/V40H）——wasm 解释/GC 语义 + host 启动下量级差异符合预期，且本仓库为
**wasm 形态**（32 位 Int、KEEP_LAST=33），**不与 native 数字直接对等**（见评估 §2.4 / 方案 §3.2：主口径是
层② wasm 对 wasm）。

## 3. 口径与做法（落实方案 D14/D15 + 评估 §2/§3）

### 3.1 cmd/bench 设计要点（对应评估 §2.3「防空循环」与 §3 #2）

- **消费 build 的 Result**：循环内对每次成功 build 的 QRCode 累加 `size`、代表性模块字节（左上/右下/中部
  各 1 个，`get` 为 O(1) 直接读）与 mask/mode/ecl/version 序号进 checksum，循环外只输出一次总量。这保证
  「只计时不计输出」不会被编译期判为无副作用而整段裁成空循环——基准测的是真实 QR 路径成本。
- **Err 兜底**：固定版本 + ecl H 在容量富余下绝不会 `Err`，但仍 `match` 显式处理（`Err` → abort），避免
  `unused_result` 告警挡门禁。
- **迭代数可调**：默认按版本各配一档（V03=2000 / V10=400 / V40=40），也接受 argv 覆盖：`-- <点> <N>`。
- **不内置纳秒钟**（D15）：跨后端 host 计时更一致；命令只稳定产 checksum，耗时全交宿主 `time`。

### 3.2 scripts/bench.sh 设计要点（对应评估 §3 #5「预留层②入口」）

- 用 bash 内建 `time`（`TIMEFORMAT='%R'`）对 点×后端 整程重复 R 次取最小（剔冷启动，对齐 wasm §5.2）；
  浮点比较用 `awk`（不依赖 `bc`）。
- 预留 `FAST_QR_WASM` 环境位：设置后脚本打印层②驱动提示（实际 JS 宿主驱动需检出 fast_qr 产物，见 §4）。
- `R=<n>` 可调重复次数；`--no-wasm` 只跑主推后端 wasm-gc 供快速调试。

## 5. 门禁与收尾（AGENTS §二.4 / 方案 §5）

```bash
export PATH="$HOME/.moon/bin:$PATH"
moon fmt && moon check --deny-warn && moon test
for t in wasm-gc wasm; do moon build cmd/bench --target $t --release; moon test --target $t; done
```

`cmd/bench` 双后端 release 构建通过；`lib` 公共 `.mbti` **零漂移**。native 不进 CI（需 C 编译器）。
