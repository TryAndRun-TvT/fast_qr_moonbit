## 0. 一句话结论

S5 掩码评分（`score.mbt` 的 N1/N2/N3/N4）与自动择优主循环（`placement.rs:85-119` 对应 MoonBit
`create_auto_qr`）**对照参考逐行等价、无正确性 BUG**：N1/N3 `line`、N2 `score_squares`、N4
`score_dark`、`create_auto_qr` 8 轮择优（占位 Format → 择优 → 真实覆写 → apply，并列取低位）均与
fast_qr 参考逐字一致。唯一发现是**注释口径失实**：固定 mask 路径 `create_fixed_qr` 实际**跳过 8 轮
评分**（只 apply 一次用户 mask），但 `qr.mbt` 注释仍写「仍评估、但用用户的」——已修正为如实表述。
另有 2 条非阻断优化建议（§4）供后续 S6/S9 承接。

## 2. 发现并落地（非正确性）

### 2.1 【已修正·注释口径】固定 mask 路径注释「仍评估、但用用户的」失实

- **现象**：`qr.mbt` 中 `QRCode::build` 的两处注释（函数文档注释 + `Some(m)` 分支行注释）均写
  「`Some(m)` …（仍评估、但用用户指定的）」/「指定固定掩码：仍评估但用用户的」，暗示固定 mask 时
  MoonBit 仍会跑 8 轮评分。
- **实际行为**：`Some(m)`/`build_fixed` 走 `create_fixed_qr`（`placement.mbt`）——**不跑 8 轮评分**，
  只 `apply_mask(m, size, mask_idx)` **一次**用户 mask。
- **与参考的关系**：fast_qr `place_on_matrix` 是**无条件**跑 8 轮评分选出 `best_mask`，随后
  `best_mask = mask.unwrap_or(best_mask)` 用用户 mask **覆盖**再 apply——即参考是"照跑评分但结果用用户
  的"。两者最终矩阵**输出等价**（均以用户 mask 应用一次），因此 MoonBit 直接跳过冗余 8 轮评分属
  **合理优化、非行为差异**。
- **修复**：将两处注释改为如实表述——固定 mask 走 `create_fixed_qr` 快速路径，**直接应用用户 mask、
  跳过冗余 8 轮评分（输出等价参考强制掩码旁路）**。纯注释改动，未改逻辑，`.mbti` 不变。
- **验证**：85/85 测试、双后端回归全绿（与改动前一致）。

### 2.2 【已修正·文档澄清】参考概念文档补 MoonBit 落地注记

- `docs/移植参考/专有概念/掩码与评分.md` 不变量 6 记录的是 **fast_qr 真实行为**（"评分循环照跑但结果
  被覆盖"），其本身**准确**、不应改写。
- 但为消除歧义（防误以为本仓库 fixed 分支也照跑评分），在不变量 6 下补一条 **MoonBit 落地注记**：本仓库
  `create_fixed_qr` 采用等价快速路径（跳过评分直接 apply），输出与参考强制掩码旁路等价。属合理优化。

### 2.3 【参考继承·备查】auto 路径按浅占位 Format 择优

- `create_auto_qr` 先在含**浅色占位 Format** 的基础矩阵上跑 8 轮评分，选中最优 mask 后才在基础矩阵
  覆写**真实 Format**（`create_matrix_format_info`）并 apply 最优 mask。
- 与 fast_qr `place_on_matrix` 时序完全一致（参考同样在占位浅 format 上择优、后写真实格式），
  **0 差异已证**，非缺陷。浅占位以 `module_type_format` 类型标记，评分时不被当作 Data 计入运行，故不影响择优。

### 2.4 【稳健增强·确认】`percent_score()` 越界 clamp 优于参考裸索引

- MoonBit `constants.percent_score(percent)` 对越界做 clamp：`percent<0` → 取 `[0]`、`percent>99` →
  取 `[99]`（`hardcode.mbt`）。
- 参考 fast_qr `dark_module_score` 为 `hardcode::PERCENT_SCORE[percent]` 裸索引，而
  `percent = dark*100/(n*n)` 理论最大可到 `100`（全暗），此时参考会**越界 panic**；MoonBit 的 clamp
  属**保险性增强**，不改变正常输入下的取值。确认保留。

## 3. 正确性复核（与参考逐字等价）

对 `score.mbt`（`line` / `matrix_score_squares` 对应 `score_squares` / `dark_module_score` 对应
`score_dark`）与 `placement.rs:85-119`（`place_on_matrix` 对应 `create_auto_qr`）逐行比对：

| 语义点 | 结论 |
|--------|------|
| N1/N3 `line`：quiet zone 双侧各补 40 / 行尾补浅只查 `light_after` / 运行只计 Data、非 Data 或变色即结算 | ✅ 逐字等价 |
| N2 `score_squares`：只查右列两格类型、连续性归零、同色 2×2 各 +3 | ✅ 逐字等价 |
| N4 `score_dark`：全矩阵暗比查表 + N1/N3 列路径（掩码后做） | ✅ 逐字等价 |
| `create_auto_qr` 8 轮择优：占位 Format → 择优 → 真实覆写 → apply，并列取低位 | ✅ 逐字等价 |
| N4 `PERCENT_SCORE`（100 项）/ Format 表 L/M/Q/H（4×8） | ✅ 与参考逐值一致（脚本提取，非手抄） |

### 3.1 加做白盒探针（验后即删，不改入库代码）

为夯实"等价"结论，临时加白盒探针验证评分语义，验后即删：

- **全暗 21 行**：N1 运行分 = 19（`21 个连续暗，21-2=19`）——N1 运行只计符号内、行无边界 quiet zone
  参与，语义正确。
- **行 `00001011101`**：N3 图案分 = **80**（行内命中 `light_before` 图案计 40 + 尾 4 浅色移位命中
  `light_after` 计 40，**双侧浅命中计两次**）——quiet zone 双侧各计 40 的语义正确。

探针验证结果与参考注释语义完全吻合，随即删除，未留入库代码。

## 4. 优化点（非阻断，供后续批次承接）

- **O1（性能 / S9）**：`create_auto_qr` 每掩码做 `apply_mask` **全量 copy** + `score` 多趟扫描，
  V40（177×177）下 8 轮成本可观。S9 可收敛为只翻 Data / 分块列缓冲评分，削减 8 轮全量 clone 开销。
- **O2（覆盖率 / S6）**：当前自动择优快照仅覆盖 **Byte 模式 & V≤10**。评分与 mode/version 无关故风险
  低，但 S6 建议先补 Numeric/Alnum + V40 数条再全量铺 60，把端到端对齐面铺得更稳。
