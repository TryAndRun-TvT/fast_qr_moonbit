# 性能测试脚本公开评审说明

> ⚠️ **历史记录**：MoonBit `wasm`(WASI) 后端已按项目决策移除，本项目现仅支持 `wasm-gc`；本文涉及的 `wasm` 后端数字与口径仅作历史留存，不再作为对外口径。

> NOTE：本仓库中的性能测试脚本已以源码形式保存在仓库中，供公开评审、复现和审计。

## 1. 评审目标

本说明用于说明本项目性能测试的真实执行入口、参数口径、脚本职责，以及数据是否可复现。重点覆盖：

- fast_qr 参考库对比
- MoonBit 生态内 QR 库对比
- 逐位对齐验证
- 单次/最小值计时口径
- 公开审阅的可复现路径

## 2. 脚本位置

### 2.1 后端角色约定（S9j 起全局统一）

同一个「MoonBit 侧」在不同脚本里可能取不同后端产物，为避免「比的是哪个后端」歧义，
全仓库统一如下术语（脚本头部注释、本文与 README 一致）：

| 术语 | 含义 | 在对比中的角色 |
|------|------|----------------|
| **`wasm-gc`** | `moon.mod` 的 `preferred_target`，**唯一支持的、实际分发形态** | **对外性能/体积对比口径** |
| `wasm`(WASI) | 已按项目决策**移除**（连同其驱动脚本） | 仅历史记录，**不再出现于脚本/口径** |

- 性能层②：`scripts/bench-layer2.sh` → `gc-compare.mjs`（`wasm-gc` vs fast_qr，S9j）。
- 体积：`wasm-gc` 为唯一列（含 `cmd/qr-min` 纯库调用探针，S9i）。
- 后端已收敛为单一 `wasm-gc`，不再有「跨后端自比」。

### 2.2 脚本清单

仓库中已存在并公开的脚本如下（括号内为后端角色与对应文档）：

- `scripts/bench.sh`（三基准点基准，`wasm-gc`；非 vs fast_qr）
- `scripts/bench-layer2.sh`（层② 对比入口；**`wasm-gc` vs fast_qr**，S9j）
- `scripts/gc-compare.mjs`（层② 驱动：`wasm-gc` vs fast_qr，S9j）
- `scripts/build-fast-qr-wasm.sh`（fast_qr 侧产物）
- `scripts/setup-fast-qr-wasm-env.sh`
- `scripts/bench-size.sh`（产物体积对比入口，S9f/S9g/S9i；取 `wasm-gc`）
- `scripts/wasm-size.mjs`（体积对比驱动，S9f/S9g/S9i）

这些脚本均位于仓库源码目录中，且可直接执行，不依赖私有配置。

## 3. 执行方式

### 3.1 Rust/fast_qr 参考库对比

```bash
cd /workspace
export PATH="$HOME/.moon/bin:$HOME/.cargo/bin:$PATH"
bash scripts/bench-layer2.sh
```

说明：

- 脚本会先准备 `wasm32-unknown-unknown` 与 `wasm-bindgen` 环境；
- 再构建 `fast_qr` 的 Node.js wasm 产物；
- 随后构建 MoonBit 的 `cmd/bench --target wasm-gc --release`（**唯一后端**）；
- 最后通过 `scripts/gc-compare.mjs` 做三基准点逐位对齐 + 跨宿主护栏 + 最小耗时比较（S9j）。
- `wasm`(WASI) 历史口径已随后端移除，相关对比工具与 `MOON_TARGET=wasm` 回退路径不再提供。

> **口径收敛（S9j）**：层② 对外对比统一取 **`wasm-gc`（`moon.mod` 的 `preferred_target`）**，
> `wasm`(WASI) 侧数字仅作历史记录，避免「比的是哪个后端」歧义。
> 详见 [S9j 层②统一 Node 对比](./S9j-层②统一Node对比-wasm-gc与fast_qr.md)。

### 3.2 直接本地对比入口

```bash
cd /workspace
export PATH="$HOME/.moon/bin:$PATH"
moon build cmd/bench --target wasm-gc --release
node scripts/gc-compare.mjs --fast /root/.cache/fast_qr_wasm/pkg/fast_qr.js \
  --moon-gc /workspace/_build/wasm-gc/release/build/cmd/bench/bench.wasm \
  --reps 3
```

`wasm`(WASI) 历史口径已随后端移除，对应构建与对比命令不再可用。

## 4. 测试口径

- 输入：`https://example.com/`（20 字节）
- ECL：H
- 版本：V03 / V10 / V40
- 掩码：自动择优
- 后端：**`wasm-gc`（默认且唯一后端，S9j 起为层②对外口径）**
- 计时：多个重复运行后取最小值（A 逐次新建 Instance / B 单实例摊薄两口径并列，B 为引用主口径）
- 对齐：逐位比较矩阵输出，校验 sha256/矩阵文本一致性；另有跨宿主（Node shim vs `moonrun`）护栏
- 环境：绝对毫秒数**绑定 Node 大版本与宿主机**（受控 A/B：v24 比 v22 使 MoonBit 侧快 18–41%、
  宿主漂移再 ±20–40%）；跨环境复现请只比「同 run 成对比值」，复现历史基线需钉对应 Node 版本
  （详见 [S9h 复测归因](./S9h-层②性能复测异常归因-Node版本与宿主漂移.md)）

## 5. 可审阅依据

本仓库中的性能数据与结论并非仅凭静态文档得出，而是来自真实执行结果：

- `scripts/bench-layer2.sh` 直接产出对比表（默认 wasm-gc）
- `scripts/gc-compare.mjs`（S9j）输出逐位对齐明细（sha256）+ 跨宿主护栏
- `fast_qr` 侧和 MoonBit 侧均在同一宿主条件下执行
- 输出包含矩阵大小、checksum 与耗时数据，可供评审者重复验证

## 6. 结论说明

本项目的性能基准重点在于：

- 真实性能脚本可复现；
- 二者输出可对照；
- 脚本与数据均在仓库中，便于公开审查；
- 对比结论来自实际执行结果，而不是宣传性描述。

这使得性能评测具备可审计性，符合公开评审要求。

## 7. 产物体积对比（S9f）

除性能外，本仓库还**同规则**量测两侧 wasm 产物体积（承接 issue #50「同一把尺子」）：

```bash
cd /workspace
export PATH="$HOME/.moon/bin:$HOME/.cargo/bin:$PATH"
bash scripts/bench-size.sh              # 全流程（环境 + 两侧产物 + 两侧探针 + 体积对比）
bash scripts/bench-size.sh --no-build   # 产物就绪时只量测
```

口径（两侧同规则，详见 [S9f 实现方案](./S9f-产物体积对比.md)）：

- ① raw 原始产物；② 剥 `custom` 段；③ `moon-wasm-opt --all-features -Oz`（**两侧同一优化器**）；
- ④ `-Oz` + 宿主胶水（fast_qr `fast_qr.js`；MoonBit 侧无）；
- ⑤ **同功能锚点**：两侧都编「无胶水单文件 + 打印、真实走 QR 核心路径」的探针
  （fast_qr 侧为外部检出 `s9f_size_probe`；MoonBit 侧为仓内 `cmd/qr-min`，S9i 起对称）；
- ⑤b **基线分解**：两侧 hello-only 探针（一行 `println`）量出「运行时地板」。

公开可审阅要点：

- 两侧**同一套规则**（同一段解析/剥离函数、同一优化器），不存在偏袒一侧的预处理；
- 所有字节级改写档位都过**语义护栏**（MoonBit `--dump` 逐字节 / fast_qr `qr_with` 三矩阵哈希 /
  裸探针导出符号），**不一致即退出码 1**；
- fast_qr 侧探针只存在于**外部检出副本**（`$FAST_QR_WASM_DIR`），**不入本仓库**；
- **探针导入面自检**：fast_qr 探针编译后立即校验 `WebAssembly.Module.imports` 必须为 **0**，
  非 0（被 `wasm-bindgen` 污染）即脚本报错退出 —— 不输出被污染的数字；
- **历史双后端（已收敛）**：S9f 初版曾并列 `wasm-gc`（`moon.mod` 的 `preferred_target`，即实际分发形态）
  与 `wasm`(WASI 兜底) 两列；`wasm`(WASI) 后端已移除，对外只保留 `wasm-gc`；
  `wasm-gc` 的 `-Oz` 用 `--all-features --disable-custom-descriptors`（否则产物宿主编译不过）；
  其语义护栏走 `moonrun`（`--dump` 三基准点逐字节）。
- 原始表与结论见 [S9f 实现记录](./S9f-产物体积对比.md) ·
  [S9g 本项目 wasm 产物体积-确认与修正](./S9g-本项目wasm产物体积-确认与修正.md)。

### 7.1 本项目产物体积速查（release）

| 产物 | 后端 | raw | `-Oz` |
|------|------|---:|------:|
| **`cmd/qr-min`（纯库调用 = 库实际体积）** | **`wasm-gc`** | 41427 B | **31365 B** |
| `cmd/bench`（基准外壳） | **`wasm-gc`** | 48038 B | **36174 B** |
| `cmd/main`（CLI 外壳） | **`wasm-gc`** | 44424 B | **33593 B** |

> 重测见 [S9o](./S9o-性能与体积数据重测-与README冗余清理.md)。

运行时地板（hello-only，`-Oz`）：`wasm-gc` **263 B** / Rust fast_qr **20052 B**
（`wasm`(WASI) 后端已移除，其体积不列）。

> **引用规范（S9i）**：`cmd/bench` / `cmd/main` 含命令外壳（argv/迭代/`--dump`/终端画/SVG），
> 其体积**不能代表库被宿主嵌入时的实际体积**；引用库体积请用 `cmd/qr-min` 口径
> （`wasm-gc` `-Oz` = 31365 B，核心净增 +31102 B）并注明后端与优化档。
> 详见 [S9i 纯库调用体积探针与库实际体积](./S9i-纯库调用体积探针与库实际体积.md)。

> **修订说明**：本说明的 S9f 初版结论把 ⑤ 同功能锚点写成「0.92×（MoonBit 更小）」，
> 那是取到了**被 wasm-bindgen 污染**的探针（58632 B）；干净探针为 45687 B，
> 正确比值是 **1.18×**。同时初版漏掉默认后端 `wasm-gc`。两处均已在 S9g 修正，
> 并已把探针污染检测升级为**脚本硬失败**。
