## 0. 一句话结论

S4 全落在 **lib/internal/matrix/**（B9：`matrix.mbt` 功能图案 + `placement.mbt` 数据放置），
外加 **lib 公共层一个最小编排入口**把「encode → structure → 放置 → 固定 mask → 写真实 Format」
串成 M1 首码。matrix 是 internal 包，**不能反向 import lib**，故矩阵在包内以
**原始字节矩阵（`Array[Int]`，每格 packed byte = 明暗 | 类型号<<1）** 承载，
lib 侧把结果包装回公共 `QRCode.data: Array[Module]`（延续 S1 D1 呈现层约定）。
S4 **不做 8 掩码择优/评分**（那是 S5/B10 最难点）；S4 只按**指定的固定 mask** 应用一次掩码、
写真实 Format，得到 M1 固定参数首码。**关键门控**：S4 的正确性验证依赖「固定 mask 首码矩阵快照」
逐位对齐，需在**一次具备 Rust 的环境**从参考源码生成快照数据（roadmap §4.1 早已立项）。

## 3. 关键架构决策与逐文件落地清单

### 3.1 决策 D3：matrix 以「原始字节矩阵 Array[Int]」为工作介质（呈现层隔离）
- **问题**：`default.rs`/`placement.rs` 在 Rust 直接操作 `[Module;31329]`。MoonBit 侧 `Module` 在
  lib（internal 不可 import），若 matrix 也要用 `Module` 会打破无环依赖。
- **方案**：`internal/matrix` 定义/约定一个**扁平原始矩阵**：
  - 表达：`Array[Int]`，长度 `size*size`（`size = v_idx*4+17`），每格为 **packed byte 的 Int 值**
    （`明暗(0/1) | 类型号<<1`，与 lib `Module.byte()` 完全同构、可互转）。
  - matrix 各函数收发的都是 `Array[Int]` + `version/ecl/mask` 的 Int 序号；**不 import lib**。
  - lib 侧（编排层）把 matrix 返回的原始矩阵逐格 `Module.from_int`/包装回 `QRCode.data`。
  - 优点：① internal 无环约束天然满足；② 掩码/评分只对 Data（`type==0`）操作，位运算在 Int 上
    最直接；③ 将来 native/wasm 性能路径可对整个 `Array[Int]` 做批量位操作而不动类型面。
- **替代不采用**：matrix 各自维护一份 `Module` 位布局（重复实现、且与 lib Module 双份易漂移）；
  或 lib 的 Module 下沉到 internal（违背 S1 D1「对外呈现类型在 lib」）。
- **遗留核对项**：`internal/matrix/module.mbt` 骨架职责描述与 lib `module.mbt` 重复。建议 S4 把
  `module.mbt` 骨架收敛为「位布局约定注释 + 一组 Int 级 bit helper」（`is_data_byte`/`set/toggle`
  等），不再保留「类型定义」措辞，避免双份类型误导（详见 §7 注意点）。

### 3.2 依赖声明（matrix/moon.pkg，B9 落时补）
按 layout §4，matrix → constants + reedsolomon（放 structure 供 placement）+ bitstream/data_encoding
（编排放 lib 时才用）。**落点切分**：
- `matrix.mbt`（纯图案绘制）只需 `constants`（information/alignment_grid/missing_bits/version 序号）；
- `placement.mbt` 放置函数本身只需本包位 helper，但其「编排 create_matrix」若放 matrix 内则需要
  `reedsolomon.structure`；
- **编排放 lib**（见 §3.5）则 matrix 包本身在 B9a/B9b 核心只依赖 constants；reedsolomon 依赖由 lib
  层在调用侧声明。为免 `unused_package`，`matrix/moon.pkg` 的 import 须与实际调用匹配——建议
  **matrix 内部完成「structure→放置→固定掩码→Format」完整编排**（对齐参考 `create_matrix` 内聚），
  故 matrix → constants + reedsolomon 两项声明并全部使用；lib 只 import matrix + data_encoding +
  constants（已有）+ 负责 select_capacity 与 Module 包装。

### 3.3 `internal/matrix/matrix.mbt`（B9a：空矩阵 + 功能图案）
对应参考 `src/default.rs`。职责与函数（以 version 序号为入参，输出在 `Array[Int]` 原始矩阵上画）：

| 函数 | 语义（参考锚点） |
|------|-----------------|
| `create_matrix(v_idx) -> Array[Int]` | 建 `size*size` 全 `light|Data` 空矩阵（参考 `create_matrix`）|
| `draw_finder(m, x, y)` | 三个 7×7 定位方块（三白边 + 黑框 + 3×3 黑核）；右上/左下同构、含分隔区浅色描边 |
| `draw_separator(m)` | 每个 finder 外沿 1 格浅色分隔（属 Empty/浅色）|
| `draw_timing(m)` | 行/列第 6 条时序线：奇偶交错黑白，跳越 finder 处按规范错开 |
| `draw_alignment(m, v_idx)` | 从 `alignment_grid(v_idx)` 取中心点，在各对齐中心画 5×5 对齐图案；跳过与 finder 重叠点 |
| `draw_dark_module(m)` | 版本无关：固定暗模块（左下 `(row=size-8, col=8)`）|
| `draw_version_info(m, v_idx)` | 仅 V7+：按 `information(v_idx)` 18 bit 在右下/左上版本信息区书写 |
| `draw_format_placeholder(m)` | 在 Format 区**写浅色占位**，为后续放置让出区域（真实 Format 在放置+掩码后写，见 §3.4）|

**关键时序铁律**（framework §五.7）：**Format 先占位 → 数据放置 → 固定掩码 → 覆写真实 Format**，
顺序颠倒会让掩码/评分误把 Format 区当数据。S4 固定 mask 路径仍遵此序（占位用浅色、其后覆写
真实 15 位 Format）。

### 3.4 `internal/matrix/placement.mbt`（B9b：之字形放置 + 固定 mask + 真实 Format）
对应参考 `src/placement.rs:36`（`place_on_matrix_data`）。S4 只做**固定 mask** 的最小路径，把 S5
的 8 轮择优主循环排除在外。核心函数：

| 函数 | 语义 |
|------|------|
| `place_on_matrix_data(m, data:Array[Byte], v_idx) -> Array[Int]` | 之字形逐位放置交织码字到 Data 区（跳第 6 列、上下行 y 方向交替）|
| `apply_mask(m, mask_idx) -> Array[Int]` | 对固定 mask 应用一次：只对 `Data` 类模块 `toggle`（参考各 mask 数学式）|
| `write_format(m, ecl_idx, mask_idx) -> Array[Int]` | 用 `constants.format_information(ecl_idx, mask_idx)` 覆写 Format 区（含 BCH 15 位布局：左上 + 分裂两段）|
| `create_fixed_qr(data_bytes, ecl_idx, v_idx, mask_idx) -> Array[Int]`（编排）| 空矩阵 → 画图案 → 之字形放 structure 交织数据 → 应用固定 mask → 写真实 Format → 返回原始矩阵 |

**放置方向细节（照抄源码，framework §五 未细列、需在实现时以参考锚点核对）**：之字形自右下角起，
列从右往左每两列一组（`col/2`），右列自上而下、左列自下而上；遇功能图案占用的模块**跳过**
（不写也不推进，仅占位）；第 6 列（时序/format 区所在列）整列跳过。放置比特源为
`structure` 返回的 5430 交织缓冲的**前 `data_codewords*8` 位**（数据码字在头部，纠错码字在其后，
统一按字节高位在前逐位放置）。

### 3.5 M1 编排入口（lib 公共层，最小接线）
参考 `qr.rs::new`/`QRBuilder::build`。S3 的 `select_capacity` 已给出 (mode,ecl,v) 三元组，S4 补：
1. `mode/ecl/v = select_capacity(...)`（S3，数据过大/版本过小在此已报错）；
2. 编码：`@data_encoding.encode(input, ecl_idx, mode_idx, v_idx)` → `CompactQR`；
3. 纠错交织：取 `encode.data[0 .. data_codewords]`（`Array[Byte]`）→ `@reedsolomon.structure(..., v)`；
4. 放置：调 matrix 的 `create_fixed_qr`（固定 mask = `Some(m)` 时用指定 mask，`None` 时先用 mask 0
   占位、真择优留 S5）；
5. 收尾：把原始矩阵逐格包装为 `Module`，填 `QRCode` 的 `version/ecl/mask/mode` 元数据。

> **范围切分建议**：S4 若不想一步卷入 lib 的 `QRBuilder` 全量 public builder（S6 公共面再补），
> 可先落一个 lib 内部/半公开的 `qr_code_fixed(...)` 组装函数（select_capacity→…→QRCode）即可闭环
> 「M1 固定 mask 首码」；`QRBuilder` builder 壳与黑盒 public 面随 S6。推荐后者，理由同 S3 §3.5。

## 5. 方案取舍一：S4 固定掩码的「8 种全实现 vs 延后 5/6」

### 5.1 roadmap 原意
S4 标「固定 mask 首码」，S5 才做「8 掩码 + 4 评分 + 择优」。S4 的掩码只需**按一个固定 mask 应用**。

### 5.2 建议：S4 先把 8 种掩码数学式全实现、但不做评分/择优
核验后认为：固定掩码一旦要支持「任意指定 mask」，8 种数学式就得都在（用户可能指 0..7 任意）；
而掩码实现（datamasking.rs:31-160，~130 行）独立于评分（score.rs，201 行），**可独立快照验证**，
不依赖择优。与其 S4 只写 1 个掩码再 S5 补齐 7 个造成返工，不如 **S4 把 8 种掩码数学式全落
（放 `datamasking.mbt`，参考 roadmap B10 前半），S5 只做评分 + 8 轮择优主循环**——这与 roadmap
原切分一致（datamasking 属 B10，但其中「掩码实现」与「择优」天然可分）。

### 5.3 若想更小步（备选，记录不推荐）
S4 首码固定掩码只用掩码 0（数学式 `(x+y)%2==0` 最简），把 8 种全实现压到 S5。缺点：S5 一次性写
8 种 + 评分 + 择优耦合度大、难独立验证；推荐 §5.2 全实现 8 种（每种有独立数学式可单测），见 §6。

## 8. 风险与评估

| 风险/难点 | 评估与对策 |
|-----------|-----------|
| matrix 无法用 lib Module（无环）| **D3**：原始字节矩阵 `Array[Int]` 为介质，lib 收尾包装；与 lib `Module.byte()` 同构可互转 |
| 快照生成需 Rust 环境、当前缺失 | roadmap §4.1 立项；S4 首码快照作为第一个产物，需在具备 Rust 环境跑一次并入库（同 S2 大表策略）|
| 呈现层 module.mbt 与 lib module.mbt 双份语义 | D3 收敛 matrix/module.mbt 为 helper + 注释，消除「类型定义」误导 |
| 8 掩码数学式写错（尤其 5/6 共用 6×6+OFFSETS）| 每种掩码独立数学式可单测；快照首码多选 mask 0/1/3/5/6 交叉验证（§6.1）|
| Format 占位/覆写时序颠倒 | framework §五.7 铁律 + 快照对齐锁死；真实 Format 用 `format_information` 查表不手算 |
| 之字形跳列/方向细节易错 | 参考 `placement.rs:36` 逐坐标核对 + 固定掩码首码快照逐位对 |
| S4 范围膨胀（8 掩码算不算 S5）| §5 取舍：掩码实现（B10 前半）随 S4 落、评分择优（B10 后半）留 S5；与 roadmap 分批语义兼容 |
| M1「CLI 输出」依赖 to_str(S7)| §6.3：S4 可用 lib 最小矩阵打印占位抽验，或把 CLI 条款顺延 S6；二选一在实现时定，不改 S4 核心范围 |
| 性能（每格一次分配/包装）| 功能正确优先；S9 性能前不做微优化（roadmap §3.3「先正确后优化」）|

> 一句话评估：S4 风险集中在**放置方向/跳列坐标细节**与**快照生成环境缺失**两点；前者用固定掩码
> 首码快照逐位对齐兜底，后者是 roadmap §4.1 已立项的一次性 Rust 环境任务。S4 在 S3/S2 底座上
> 推进路径清晰，是 M1→M2 的必经关卡，且其产出（可放置的原始矩阵 + 8 掩码）直接是 S5 择优的输入。
