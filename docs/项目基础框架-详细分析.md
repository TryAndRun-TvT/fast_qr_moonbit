## 二、移植对象框架（fast_qr v0.14.0 精华）

> 详细依据：[fast-qr-架构.md](移植参考/fast-qr-架构.md)、[核心编码管线](移植参考/模块/核心编码管线.md)。

### 2.1 形态与规模

- Rust 库 + WASM npm 双形态；核心代码**零第三方运行时依赖**；`wasm`/`js` 由同一份核心编译。
- 代码量：核心管线约 **3280 行** + convert/wasm 约 **1170 行**；测试约 7100 行（1.6 倍于核心）。

### 2.2 模块图与依赖方向（单向）

```
encode → compact → polynomials ──┐
version / ecl / hardcode（常量表）─┼→ placement / default → datamasking / score → qr
                                 │
convert / wasm（外围，消费 QRCode 矩阵）
```

核心单向依赖链：**encode → compact → polynomials → placement → qr**，禁止反向引用；
`convert`/`wasm` 只读矩阵，属外围可独立裁剪。

### 2.3 7 条核心性能决策（移植时**必须保留其语义**，细节见 ARCHITECTURE §核心设计决策）

| # | 决策 | 移植要点 |
|:-:|------|---------|
| 1 | 固定大小矩阵 `[Module; 177*177]` | 按行存储的一维固定数组，运行时零扩容 |
| 2 | 单字节模块编码 | bit0 明暗 + bit1-3 类型（见 §五.1） |
| 3 | 预分配比特缓冲 `CompactQR` | 按版本上限一次分配，编码期零扩容 |
| 4 | 编译期常量表 | 容量/分组/格式信息/GF 表全静态，运行时只查表 |
| 5 | 掩码择优成本控制 | 基础矩阵只建一次，8 轮 `clone`+掩码+评分 |
| 6 | 无分支热点 | `push_bits` 无分支；GF 除法查表替代模运算 |
| 7 | 体积优化链 | `opt-level='s'`+LTO 等（Rust 侧）；WASM 侧 build-std+wasm-opt（MoonBit 侧对应见 §七 P2） |

### 2.4 公共 API 面（MoonBit 侧 API 设计的功能参照，非签名照抄）

- 核心：`QRBuilder`（new/mode/ecl/version/mask/build）、`QRCode`（data/size/version/ecl/mask/mode、`Index`、`to_str`）、`ECL`、`Version`、`Mode`、`Mask`、`Module`/`ModuleType`、`QRCodeError`。
- 转换：`SvgBuilder`/`ImageBuilder`（shape/margin/color/fit_width…to_str/to_file/to_bytes）。
- JS：`qr(content)->u8[]`、`qr_svg(content,SvgOptions)->string`。
- 性能契约（对照基准，供 P2 透明对比）：V03H 82.2us、V10H 269.3us、V40H 2436.2us（约 6.5-7.9 倍于 `qrcode` crate）。

> 详见 [fast-qr-接口.md](移植参考/fast-qr-接口.md)。MoonBit 公共 API 采用 MoonBit 惯用命名由 P0 黑盒测试锁定（§七），
> 能力面与上表对齐即可，不必保留 Rust 链式 builder 的逐字签名。

## 三、MoonBit 目标框架

### 3.1 骨架布局（已定，维持不变）

与 `moon new` 官方骨架一致：无 `src/`，库源码在模块根、CLI 在 `cmd/main/`、黑盒/白盒测试
分文件。**不要**为未来子包提前建空目录（会触发 `unused_package` 或空包问题）。

### 3.2 目标包架构（实现到一定复杂度后按信号落地）

来源：[core-仓库布局参考与目标架构.md](./core-仓库布局参考与目标架构.md) §四。

```
fast_qr_moonbit.mbt                 # 根公共包：对外 API（QrCode / 编码入口等）
├── version.mbt / ecl.mbt 等         # 公共枚举与常量（对调用者可见）
├── *_test.mbt / *_wbtest.mbt       # 黑盒/白盒测试
└── internal/                        # 内部实现（对模块外不可见，各子包带 moon.pkg）
    ├── matrix/                      #   矩阵：Module 单元、功能图案、放置、掩码、评分
    ├── reedsolomon/                 #   GF(256) 纠错与交织
    ├── bitstream/                   #   数据位流封装（CompactQR 的 MoonBit 对应）
    └── data_encoding/               #   编码模式（Numeric/Alnum/Byte）
```

**拆包判据**（本仓库已按方案 3 落地 `lib/` + `lib/internal/` 分层；此判据适用于 internal
包内的进一步拆分）：`.mbt` 过多且分层明显；某内部实现需独立测试且不便走公共 API；
公共 API 出现不想进 `.mbti` 的类型。

### 3.3 与仓库约定的一致性

- 库文件位于 `lib/`（方案 3，模块根不建包）：多 `.mbt` 共享 `lib/moon.pkg`；
  测试文件遵循 `_test`（黑盒，`@lib`）/ `_wbtest`（白盒）/ 源码内联 `test { }` 三类分工；
  贴近实现的断言用内联块（不影响产物体积）。
- 拆包后：每个子包一个 `moon.pkg`，依赖在使用方声明；`lib` 可依赖 `lib/internal/*`，
  内部子包不反向依赖 `lib`；跨子包依赖方向保持参考库的单向链。
- 公共 API 全带 `///` 文档；弃用代码放 `deprecated.mbt`；`.mbti` 作为对外接口快照。

## 五、移植必须保留的语义与高风险清单

> 下列语义是参考库「规范未明说的实现决策」，按规范重写必然做错，**必须原样保留**并通过快照/黄金测试锁定。
> 详细出处：[跨语言重写评估](移植参考/专有概念/跨语言重写评估.md) §6、[掩码与评分](移植参考/专有概念/掩码与评分.md)、
> [GF256纠错与交织](移植参考/专有概念/gf256-纠错与交织.md)、[CompactQR](移植参考/专有概念/compact-qr.md)。

| # | 必须保留的语义 | MoonBit 落地注意 |
|:-:|---------------|-----------------|
| 1 | **Module 位打包**：bit0 明暗、bit1-3 类型（8 种，判别值保持 `<< 1`）；掩码只 `toggle` Data 类模块 | 用 `Byte` 或单字节容器承载；类型/明暗读写、翻转须与位布局一致；enum 若用需保证判别值 |
| 2 | **固定大小矩阵**：`[Module; 31329]` 一维按行存储，`size = version*4 + 17` | 用固定大小容器一次分配；避免逐点堆分配 |
| 3 | **KEEP_LAST 表位宽**：wasm32 33 项 vs 64 位 65 项 | 后端位宽差异（`wasm`/`wasm-gc`/`js`/未来 native）需在实现时核对截断位数 |
| 4 | **常量表全静态**：容量、分组（u32 位打包 `(count<<24)|(size<<16)|…`）、格式信息、LOG/ANTILOG、生成多项式 | 表数据用**脚本从参考库源码提取**（避免手抄错），运行时只查表 |
| 5 | **掩码择优成本控制**：基础矩阵建一次，8 轮 clone+mask+score，无增长分配 | 用预分配缓冲轮询，勿每轮重建矩阵 |
| 6 | **评分 4 条规则细节**：N1 连续同色(N-2)、N2 2x2(3)、N3 11 位窗口命中(40)、N4 暗比表；**列评分必须在掩码后**；2x2 触及功能模块不计分；quiet zone 行首尾补 4 浅色、双侧浅命中计两次 | 以上为真实 bug/决策产物，逐条对照实现 + 快照验证 |
| 7 | **Format 占位→覆盖时序**：先写占位、掩码择优后再写真实格式信息 | 顺序颠倒会让评分把 Format 区当数据，掩码选择与原版不一致 |
| 8 | **GF(256) 语义**：LOG/ANTILOG 查表、`%255` alpha 加法、固定上限数组（`[255]`/`[5430]`）、数据区「逐块跨字节」与纠错区「逐字节跨块」交织方向相反 | 默认数值溢出/取模语义需与 u8 对齐（掩码或显式类型），并用黄金数据覆盖 |
| 9 | **编码规则**：Numeric 3 位一组 10bit、Alnum 2 字符 11bit、Byte 直拷；模式回退 Numeric→Alnum→Byte；terminator + 8 对齐 + `[236,17]` 填充 | 位宽不规整是 CompactQR 存在的原因，逐条对照编码表 |
| 10 | **版本容量匹配**：`Version::get` 依据 (mode, ecl, len) 选最小容量版本；错误面 = 超容量/指定版本过小 | 容量表需逐版本黄金测试；指定 version/mask API 也要有测试 |

## 六、验证与验收策略

### 6.1 双层验证（采纳 [跨语言重写评估](移植参考/专有概念/跨语言重写评估.md) §5.3）

| 层 | 内容 | MoonBit 落地 |
|----|------|-------------|
| 快照对齐（端到端） | 相同 (content, ECL, version/mask) 输入下，生成矩阵与参考库**逐位一致** | 任一模块翻译错误在此暴露，一次运行覆盖全管线 |
| 黄金数据（单元） | 抄自参考库 `src/tests/*` 的期望值表（version 容量、polynomials 除法、structure 交织等） | 快照失败时收缩定位到具体函数 |

**前置（P0 第一步）——准备期望值来源**，三选一：

1. 在具备 Rust 环境的机器检出一份 fast_qr v0.14.0，跑一次快照生成器，导出约 60 条
   (版本×ECL×模式 + 边界 + 强制参数) 矩阵 JSON；
2. 直接转译其 `src/tests/*.rs` 黄金数据表；
3. 引入 Nayuki qrcodegen 作第二参照（推荐，三向交叉）。

### 6.2 MoonBit 侧断言/快照机制

- 源码内联 `test { }`：贴近实现的位级断言，不影响产物体积（实证见最佳实践 §二.3）。
- `_wbtest.mbt`：私有函数与内部结构（matrix 放置、score 各规则、push_bits 位操作）白盒断言。
- `_test.mbt`：公共 API 行为（构建结果、错误面、`to_str` 输出）黑盒断言。
- `inspect(...)` + `moon test --update`：结构复杂的输出（如特定版本矩阵行串）做快照。
- `.mbti`：`moon info` 生成的公共接口快照，作为 API 面的回归护栏。

### 6.3 每轮改动收尾门禁（AGENTS.md 约定）

```bash
export PATH="$HOME/.moon/bin:$PATH"
moon fmt && moon info && moon check --deny-warn && moon test
for t in wasm-gc wasm js; do moon build --target $t --release; moon test --target $t; done
```
