## 2. 落地要点与决策

### 2.1 cci_bits（B2 补丁，决策 D1）
参考 `hardcode.rs:302 cci_bits` 三段三分支（Numeric/Alnum/Byte 各自 v≥V27、v≥V10 升档）。
按决策 D1 与 `data_bits` 同归 `capacity.mbt`，纯查序号 `if/else` 三分支，不做过度建表。
- 越界护栏：`version_idx` 超界按最近端点（<0→V1、>39→V40）、`mode_idx` 超 2 → Byte；
- Byte 只在 V10(idx 9) 升 16、V27 不再涨（与源码一致），表头「<9」即版本号 <10。

### 2.2 encode.mbt（B7）：照抄 encode.rs 语义
- **编排**：写模式头 + CCI + 数据 → `add_terminator`（补 `min(data_bits-len, 4)` 个 0）→
  `pad_to_8`（对齐字节）→ `fill`（[236,17] 铺满 max_bytes×8 预留区）。`encode` 返回的 `data`
  即 S4 structure 输入（前 data_bits 位须逐位一致）。
- **Numeric**：模式头(0b0001,4) → CCI → 每 3 位合成 10bit；余 1 位写 4bit、余 2 位写 7bit。
- **Alphanumeric**：模式头(0b0010,4) → CCI → 每 2 字符 `a*45+b` 写 11bit；单余写 6bit。
- **Byte**：模式头(0b0100,4) → CCI → `push_u8_slice` 直拷。
- **best_encoding**：全数字→Numeric(0)；否则全 `is_qr_alphanumeric`→Alnum(1)；否则 Byte(2)。

### 2.3 MoonBit 适配（与方案 §3.4 一致）
- `ascii_to_alphanumeric` 用普通 fn + ASCII 区间/match（32 位 Int 比较）；小写字母不属于 QR alnum。
- 参考 `tests/encode.rs` 的 16 位 `u16` 中间量位段转译为 **byte 数组 + Int 位运算**等价改写。
- fatal 用 `abort("msg")`（本版 MoonBit `panic` 不收参），供内部非法 alnum 字符兜底。

### 2.4 B8：lib 公共层首次 import internal（无环）
`QRCode::select_capacity(input, mode?, ecl?, version?) -> Result[(Int,Int,Int), QRCodeError]`：
- mode None → `@data_encoding.best_encoding`；ecl None → 默认 Q(2)；
- version_for 得最小适配版本，`-1`（V40 装不下）→ `Err(EncodedData)`；
- 指定 `uv >= 最小` → 用 uv；否则 `Err(SpecifiedVersion)`。
- lib/moon.pkg 新增对 `data_encoding` + `constants` 的 import（internal 不反向依赖 lib，无环）。
  `QRCodeError` 两变体在容量选择错误路径上被真实构造，解除 S1 的 `unused_constructor` 推迟。
- 本阶段只做「容量选择」；`create_matrix`（S4）与 `QRBuilder` 公共壳随 S4/S6 接入此路径。

## 5. 偏离与说明
- **`encode_numeric` 余数实现**：源码以 `i%3` 在累加后判别 Single/Double；本实现直接按
  `rem = len%3`（余 1→4bit、余 2→7bit）等价改写，语义一致（Python 已对 '5894'/'58949'/'589491'/
  '200505150001' 逐字节复核）。
- **ascii_to_alphanumeric 早期 bug**：首版把 `*`（ASCII 42）误写为 `38`，致 `*` 落 `abort`；
  黄金测试 `ascii_alnum_map` 捕获后修正为 `42 => 39`。此类映射必须对照参考逐字符核对。
- **测试输入构造**：`s(s)` 助手用 `for ch in str` + `ch.to_int().to_byte()`，规避 `to_bytes()`
  已弃用告警（deny-warn 门禁）。
