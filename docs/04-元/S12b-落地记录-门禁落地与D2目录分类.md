### 13.1 复现的口径缺陷（PR #80 之后的独立核验）

| # | 现象 | 根因 | 危害 |
|:-:|------|------|------|
| B1 | `moon` 不在 `PATH` 时，② 打印 `line 76: Total: command not found`，报错**指向工具链缺失** | `export PATH="$HOME/.moon/bin:$PATH"` 不足以覆盖「宿主未装工具链」的调用面 | **误诊**：README 让读者装工具链/开替我上班，而真因可能只是 PATH；也让 CI 外调用者困惑 |
| B2 | ② 的 `sed -E 's/.*Total tests: ([0-9]+).*/\1/p'` 用 `.*` **宽匹配** | moon 失败输出的**末行提示语本身含** `Total tests: ...`，被当作计数行 | **假绿**：解析失败时 `actual` 看似有值，「计数漂移」这道闸门**静默失效** |
| B3 | ③ 只用 `grep -qF "$base"` 判「是否入索引」 | basename 子串匹配 | **假绿两种**：① 文件未被索引、但 basename 恰好出现在别处（如提到篇名）也算过；② 索引里写了、文件已删（**反向缺口**），`docs-link-check.sh` 遍历的是**实际文件**，看不到 |
| B4 | ③ 只判「出现在索引里」 | 判据过宽 | 把一篇**只塞进 §8 全量清单**的文档也算「已入索引」——可发现性并未达成（§3.4 的可读性问题原样保留） |
| B5 | ③ 的 basename 比较对 `docs/移植参考/**` **误判** | 该 12 篇在索引里写作 `./移植参考/xxx.md`（**带子目录**），basename 集合匹配不到 | **假红**：③ 上线即报 12 处「未入索引」，而它们其实**已被 §7.4 逐篇显式链接** |
| B6 | ③c（本轮新增）最初写成 `git ls-files 'docs/*/*/*.md' 'docs/*/*/*/*.md'` | glob 深度**只到三层**，而 `docs/移植参考/README.md` 恰好是三层 | **漏检**：这条 glob 唯一要抓的就是它，却抓不到（自证式漏检） |

> **B2 + B3 + B5 是同一条教训的三个面**：**判据本身要有反例**。
> 只跑「期望变红」的负向验证不够，还要跑「期望**不变红**」的正向回归（B5 就是被正向回归抓到的）。

### 15.3 E2 · 状态头日期漂移提示

| 项 | 内容 |
|----|------|
| 产物 | `scripts/docs-date-check.sh`（**永不 exit 1**，除文件系统级错误） |
| 口径 | 状态头 `日期` < 该篇**末次实质 commit** 日期 → 提示 |
| 噪音抑制（三重，实跑调参） | ① 滤「只动状态头」的 commit；② 滤「横切大批量」commit（改动文件数 > `MAX_FILES`，默认 3）；③ 改动行数阈值 `MIN_LINES`（默认 10） |

> 「实质修订」本身是启发式。误判代价不该是红门禁——这与 §14 E2 立项时的判断一致。
> **副作用自查**：本项**要求 git 历史**（本环境可用）；若在无 `.git` 的归档面运行，
> `git log` 输出为空 → 全部计入「无实质 commit 记录」，静默跳过（不误报）。

## 18. 目录策略评估 + 门禁 B7 加固（第六轮：先问「该不该建目录」，再补假绿）

> **动因（ISSUE #78，D2 落地后复审）**：「每实现一个特性，是否应当生成一个文件夹？」——
> D2 刚把 `docs/` 从「47 篇平铺」收敛为「4 类」，紧接着的问题是**类目与特性/模块的关系**：
> 该不该按特性（或模块）再建一层目录？
>
> 本轮做两件事：**① 给出目录策略的判定规则与明确不做的理由**（§18.1–§18.3）；
> **② 用这轮实测**如实登记一条**门禁自身的新假绿**（B7）并加固（§18.4–§18.6）。
> **零文件移动**（本轮**不**新增任何目录）；代码侧零改动（未触碰 `lib/**` / `cmd/**` / `.mbt` / 黄金值）。

### 18.1 结论先行

1. **文档目录按「读者意图」分，不按「特性/模块」分**——D2 已定的 4 类 + `移植参考/` 是**终点**，
   **不新增特性级目录**（判据见 §18.2）。
2. **代码侧目录按「模块/包」分**——本仓库**已经在这么做**（`lib/internal/<模块>/` 各带 `moon.pkg`），
   即「一个特性 → 一个包目录」成立；但**包 ≠ 文档目录**，见 §18.3 的两套坐标系。
3. **文件夹不是零成本的**：每个新目录都新增一条「归类决策 + 导航面 + 门禁面」的维护债；
   本仓库已有的门禁（③/③b/③d/④）与索引（`docs/README.md` §0.5/§7/§8）**只在类目稳定时**才可复跑。

### 18.2 判定规则：什么时候**该**建新目录（本仓库口径）

| # | 规则 | 本仓库现状对照 |
|:-:|------|----------------|
| R1 | **读者意图不同**才分目录（不同的人问不同的问题） | ✅ D2 的 4 类正是此判据（改代码 / 审计数据 / 复盘决策 / 改文档） |
| R2 | 该域**≥3 篇且会持续增长**——1–2 篇用命名前缀即可，不必建目录 | ✅ `S9*`（18 篇性能）先靠文件名序号，D2 才归入 `02-证据/` |
| R3 | 该域有**独立的生命周期**（谁维护、何时淘汰） | ✅ `移植参考/`（外部语料，S11 §6.3 判定不并入主域） |
| R4 | 新目录必须能**同时**接入三道既有门禁：索引摘要区（③）、索引反查（③b）、链接内容（③d） | ⚠️ 这是**成本项**：新目录要同步改 `docs/README.md` §0.5 地图 + §7 表 + §8 生成物 |
| R5 | **不新建「索引的索引」**：域首页用「域-索引.md」，不得用 `README.md` | ✅ 门禁 ③c 强制 |

**反向判别（不该建）**：仅「文件名看起来同族」（如 `S9b…S9r`）**不构成**目录；
「以后可能会多」属**未来式设计**（Spec Kit 的 Simplicity Gate / Anti-Abstraction，S12 §5.1），禁止。

### 18.3 为什么「特性」**不**直接映射为「文档目录」

| 维度 | 代码侧（模块/包） | 文档侧（读者意图） |
|------|------------------|--------------------|
| 切分依据 | **实现边界**（依赖方向、可测性、编译单元） | **读者问题**（我要改代码 / 我要审计数据 / …） |
| 数量 | 随特性线性增长（当前 `lib/internal/` 5 个子包） | 应**稳定且少**（当前 4 类 + 1 域，S12 §6.1 D2） |
| 横切事实 | 一个包内实现细节 | 一篇文档常**跨多个特性**（如 `S9n` 同时覆盖内联/常量化/位流） |
| 变更频率 | 随代码 PR 变 | 随「结论变更」变，比代码**慢** |
| 门禁 | `moon check/test` | 死链 / 章节引用 / 索引双向 / 规模（本轮又加 ③d） |

> **一句话**：**特性是代码的切法，读者意图是文档的切法**。若按特性建文档目录，
> `S9n` 这类**跨特性**篇章会被迫选边，或**复制进多个目录**——两种结果都劣化。
> Diátaxis 的立场与此同源（S12 §2.2）：文档类型**不可混写**，但切法是**读者导向**，不是实现导向。
>
> **例外（当特性自带独立读者域时）**：若某特性会产出**成体系的外部读者文档**
> （如独立 SDK 的接入指南），才按 R2+R3 立项。本仓库当前无此形态（`docs/移植参考/` 是唯一先例，
> 且它是**外部语料**而非本项目特性）。

### 18.4 这轮实测发现的假绿（B7）：③ 的「摘要区」判据自带后门

> 起因：想验证「删掉索引里一条登记行，门禁会不会红」，结果**不红**。逐条定位：

| # | 现象 | 根因 | 危害 |
|:-:|------|------|------|

| **B7b** | 判据 `b7 < i < b8 or i < b7` 把 **§8 之后**的行也算作摘要区 | 尾部收尾说明那行含链接，即被算作「摘要区按名链接」 | **判据过宽**：与 ③ 设立目的（可发现性）不符 |
