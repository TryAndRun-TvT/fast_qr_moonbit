## 2. F1：`check --deny-warn` 红 —— 工具链升级引入的 dev79（**已修**）

### 2.1 现象与归因

`moon 0.1.20260904 → 0.1.20260920` 后，`moon check --deny-warn` 报 **16 个 error**，全部是同一类：

```
Error Warning (implicit_impl_as_method): The methods equal, not_equal from
`impl Eq for ECL` are implicit promoted as regular method for `ECL`.
This behavior is deprecated ... Add a `pub extend ECL with Eq::{...}` declaration
or manually define regular methods ... If the promotion is not desirable, add `#deprecated` on the `extend`.
```

命中 **8 个公共类型 × 2 条**（`Eq` 与 `Debug` 各一）：`ECL / Mask / Mode / ModuleType / Module / QRCodeError / Shape / Version`——
它们都写 `derive(Eq, Debug)` 且是 `pub(all)`。

根因：新工具链**废弃**了「`derive` 出的方法在 `pub(all)` 类型上自动提升为常规方法」这一行为；
`derive(Eq, Debug)` 本身没错，错在**默认会把 `equal/not_equal/to_repr` 当成可直接调用方法暴露**。

### 2.2 移除可行性分析（3 个候选，择最干净者）

| 方案 | 做法 | API 面影响 | 结论 |
|:----:|------|-----------|:----:|
| A | `#deprecated pub extend X with Eq::{...}` + `Debug::{to_repr}` | `.mbti` **新增 24 个** deprecated 符号 | 可用但污染契约 |
| B | `warnings = "-79"`（包级关闭该编号） | `.mbti` **逐字节不变** | **采用** |
| C | 手写 `equal/not_equal/to_repr` | 需 8 类型 × 3 方法手写，且**扩大**可调用面 | 否决 |

选 **B**：本库对 `derive(Eq, Debug)` 的用法是**标准用法**，并**不打算**把这三个派生方法纳入对外可调用面——
编译器错误文本本身就把 `#deprecated extend` 列为「不期望提升」的出口；包级 `-79` 是同一语义的**零 API 污染**写法。
且仓库已有先例（根 `moon.pkg` 的 `warnings = "-29"` 关 `unused_package`），做法同构。

**实证**（`lib/moon.pkg` 追加 `warnings = "-79"` 后）：

```bash
moon check --deny-warn   # → Finished（0 warnings, 0 errors）
moon info && diff <(基线 .mbti) lib/pkg.generated.mbti   # → 无输出（逐字节相同）
moon test                # → 147 全绿
```

### 2.3 判据

- 关闭的是**语言层的「隐式提升」告警**，不是「`Eq`/`Debug` 实现有误」——后者若有问题，`derive` 会直接编译失败；
- `.mbti` 逐字节不变 ⇒ **对外契约零变化**，不触发 S11 §7-5「改公共面须同步文档」的联动成本。

## 3. F2：潜伏的 382 × dev25 —— 修好 F1 才暴露（**已修**）

### 3.1 现象

F1 修好后，`check --deny-warn` 立刻转为 **382 个 `test_unqualified_package`（dev25）**：

```
Warning (test_unqualified_package): `ECL` is implicitly imported in test. Use `@lib.ECL` instead.
```

**为什么之前看不见**：`--deny-warn` 在 16 个 error 处即中止，382 条告警根本没机会升级；
一旦 error 清零，它们就全部浮出。这是典型的「**修一个红，暴露下一层红**」——
文档/脚本里若只记录「门禁红」，会误判体量。

### 3.2 分布与处置

`dev25` 是**新工具链对「黑盒测试隐式导入」的废弃**：`*_test.mbt` 属包外，引用本包类型
必须写 `@lib.X`。分布（8 个黑盒测试文件，共 382 处）：

| 文件 | 处数 |
|------|:----:|
| `lib/fast_qr_moonbit_test.mbt` | 119 |
| `lib/m1_snapshot_test.mbt` | 69 |
| `lib/s6_snapshot_test.mbt` | 63 |
| `lib/t4a_property_test.mbt` | 48 |
| `lib/qr_builder_test.mbt` | 31 |
| `lib/s7_svg_test.mbt` | 23 |
| `lib/s7_terminal_test.mbt` | 20 |
| `lib/s6_decode_vectors_test.mbt` | 13 |

处置：**机械限定**（`@lib.` 前缀），不改任何测试语义。
实现脚本遵循两条安全约束，避免「批量 sed 误伤」：

1. **只改代码、不改注释**（行内 `//` 之后原样保留，避免出现 `/// @lib.Module 位语义` 这类噪声）；
2. **负向 lookbehind**：只替换**未被 `@lib.` 限定、且前邻不是标识符/`.`/`@`** 的裸类型名，
   避免把 `qr.set(...)`、`Some(X)`、字符串里的同名子串改坏。

**为什么不 `warnings = "-25"` 了事**：dev25 是**正当的现代化建议**（限定包名可读性更好、且防歧义），
与 F1 的 dev79（纯「隐式提升」废弃、无语义收益）性质不同——**该改的改，该关的关**，不搞一刀切。

### 3.3 实证

```bash
moon check --deny-warn   # → 0 warnings, 0 errors
moon test                # → 147 全绿（default + wasm-gc）
moon info && diff 基线 .mbti   # → 无输出（测试不参与契约）
moon fmt                 # → 仅此批改动需要重排（行首 @lib. 使部分行变长换行）
```

## 4. F3/F4/F5：三类门禁「失真」（**已修**）

> 三者同源：**D2 目录迁移（2026-09-18，commit `7323a56`）把 `docs/*.md` 挪进了 4 个子目录**，
> 但**脚本里的硬编码路径没跟着改**。迁移由「死链 / 章节引用 / 索引双向 / 清单生成」四道门禁兜底——
> **而脚本自身的路径引用不在那四道门禁的检查范围内**，于是形成盲区。

### 4.1 F3 `docs-consistency.sh ②` —— 断链（门禁只跑了一半）

- **现象**：`sed: can't read docs/S10b-测试覆盖率报告.md` → `set -o pipefail` 下脚本以非 0 中断，
  且**②之后的所有断言（②b/③/③b/③c/③d/④/⑤）全部没跑**。
- **危险点**：脚本「红了」，但报错原因指向 `sed` 找不到文件（误诊），且**大部分断言被跳过**——
  若有人「看它红了就跳过」，实际是**用一半门禁换来的红**，比不跑更误导。
- **修**：路径改 `docs/02-证据/S10b-测试覆盖率报告.md`；并在 ①之后验证 ②~⑤ 全部执行。

### 4.2 F4 `coverage.sh --floor` —— 假绿/误诊（T5-b 根本没比对）

- **现象**：`FLOOR_FILE="docs/S10b-测试覆盖率报告.md"` 指向已不存在的路径 →
  `sed` 报错 → 与 F3 同因。T5-b 的「未覆盖行 ≤ 登记上限」**从未真正比较**。
- **修**：路径改 `docs/02-证据/...`；并按 S12b §13「输出不得静默」**显式判存在性**——
  登记处缺失 ⇒ **fail**（给出可读处置），而不是让 `sed` 的报错代替结论。
- **实证**：修后 `bash scripts/coverage.sh --floor` → `✅ 未下降（15 <= 15）`（首次真正比对）。

### 4.3 F5 `publish-check.sh ②` —— 假红（计数被告警噪声污染）

- **现象**：脚本用「黑名单日志前缀」（`Warning|Error|Running|...`）过滤 `moon package --list` 输出。
  新工具链的告警是**多行块**（`╭─[`、`│`、`╰──`、`────╯`），只按行首前缀过滤**漏掉块行**，
  于是归档条目数从 **34 暴涨到 2824**（差 2388）——一个「假红」。
- **修**：判据由「黑名单前缀」改为**白名单「条目形态」**（`^[A-Za-z0-9_./-]+$` 且非日志关键字）。
  告警噪声天然不含这类行，**对噪声免疫**。
- **负向验证**（S12b §13 要求）：构造含多行告警块 + 3 个条目的假输入，白名单过滤后**恰好 3 条**。

### 4.4 三个修复的共同教训

> **门禁的判据，不能依赖「上游工具的输出版式」。**
> 版式一变（工具链升级）、路径一变（目录迁移），`grep`/`sed` 这类**文本耦合**判据就会失真，
> 且失真的形态各异：**断链**（F3）、**静默**（F4）、**假红**（F5）。
> 处置方向：**白名单 > 黑名单**、**显式判存在**、**缺输入即 fail**。
