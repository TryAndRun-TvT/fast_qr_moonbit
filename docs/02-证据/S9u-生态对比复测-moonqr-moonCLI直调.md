# S9u · 生态对比复测：本仓库 vs `moonqr`（moon CLI 直调）

> **状态**：现行　｜　日期：2026-09-24　｜　索引：[docs/README.md](../README.md) §2
> 承接：[S9d](S9d-与moonbit生态QR包性能对比.md)（历史首跑，2026-09-06）· 口径对齐
> [S9](S9-性能基准.md)/[S9p](S9p-宿主调用面性能口径-JS向wasm传参.md)（同宿主成对比值、R 次取最小）
> 一句话结论：本仓库单次 build 比生态 `naoto24kawa/moonqr@0.2.0` 快 **2.7–4.3×**（**同 run 比值**，
> 2026-09-24，moon CLI 直调）；**首跑 2.5–4.1× 的绝对 ms 不可跨会话比较**——moonqr 同版本绝对值本次也
> 变为首跑的 ≈0.48×，纯属宿主/工具链漂移，**只有比值可迁移**。

> 本次同时修掉一个**可复跑性缺口**：S9d 的对比驱动当年在仓库外临时目录、**未入库**，
> 而 README 一度把「复跑」指到 `scripts/bench-layer2.sh`（那是 fast_qr 对比，**指错**）。
> 现已落地 `scripts/bench-moonqr.sh`（只加脚本，**不动** `lib`/`moon.mod` 依赖面）。

## 1. 议题定义

| # | 问题 |
|:-:|------|
| Q1 | 生态 `moonqr` 对比能否**一条命令复跑**（此前只有历史的临时驱动）？ |
| Q2 | 优化落地（P0/P2/P2b + 矩阵介质 `FixedArray[Int]`）后，**对 moonqr 的比值**是多少？ |
| Q3 | 与 S9d 首跑数字的差异，哪些是**本仓库改动**、哪些是**环境漂移**？ |

**明确不做**：不把 moonqr（或任何外部包）加进本仓库 `moon.mod`（会污染库依赖面/.mbti 面）；
不跨会话比较绝对毫秒（S9q 纪律）。

## 2. 方法（脚本 = `scripts/bench-moonqr.sh`，moon CLI 直调）

```bash
bash scripts/bench-moonqr.sh          # R=5（默认）
# 对比模块落在 $MOONBIT_QR_COMPARE_DIR（默认 ~/.cache/moonbit_qr_compare），不入库
```

- **取包**：`moon add naoto24kawa/moonqr@0.2.0`（**钉版本**，防包更新导致不可复现；可 `MOONQR_VERSION=` 覆盖）。
- **两侧同宿主**：均构建为 `wasm-gc --release`，均用 `moonrun <wasm>` 独立进程整程计时，**R=5 取最小**；
  同点同 N（V03H=2000 / V10H=400 / V40H=40）。
- **协议**：输入 `https://example.com/`（20B）、ECL **H**、**强制版本**、mask **自动择优**、完整 Format/版本信息。
  本仓库侧 = `cmd/bench`；moonqr 侧 = `@encode.encode(text, EcLevel::H, Some(v))`。
- **消费口径对齐**：每轮累加 `size + 3 代表格`（防死代码消除）；跨实现**不要求** checksum 一致，
  只校验**同尺寸**（29/57/177）。
- **计时用 `moonrun` 而非 `moon run`**：**两侧一致**，避免一侧额外付 moon CLI 启动开销。

## 3. 结果（2026-09-24，R=5 取最小）

| 点 | N | 本仓库 整程(ms) | moonqr 整程(ms) | 本仓库 单次(ms) | moonqr 单次(ms) | **vs 本仓库（慢多少倍）** |
|----|--:|----------------:|----------------:|----------------:|----------------:|--------------------:|
| V03H | 2000 | 322.0 | 875.0 | **0.1610** | 0.4375 | **2.72×** |
| V10H | 400 | 220.0 | 948.0 | **0.5500** | 2.3700 | **4.31×** |
| V40H | 40 | 185.0 | 747.0 | **4.6250** | 18.6750 | **4.04×** |

**与 S9d 首跑对照（⚠️ 绝对 ms 跨会话不可比，仅列比值）**：

| 点 | S9d（2026-09-06）比值 | **本次（2026-09-24）比值** | 变化 |
|----|:--------------------:|:-------------------------:|------|
| V03H | 2.54× | **2.72×** | 略宽 |
| V10H | 3.61× | **4.31×** | 变宽 |
| V40H | 4.05× | **4.04×** | 持平 |

> **为什么没有「本仓库更快 ⇒ 比值必然更大」**：两次跑的**工具链**（`moon 0.1.20260827` → `0.1.20260920`）
> 与宿主负载不同，**两侧的编译产物与绝对速度都变了**（moonqr 同版本本次绝对值 ≈ 首跑的 0.48×）。
> 按 S9q 纪律，**只有同 run 内比值可迁移**；S9d 与本表**不可**做绝对减法。

## 4. 分析与结论

1. **同语言生态里本仓库不落后**：`moonqr` 是「强制版本 + ECL H + 自动择优 + 完整输出」唯一干净可对齐的生态包
   （S9d 已核：qrc 强制路径缺 mask/Format、moonbitqrcode 固定 mask0 + 仅 L/M/Q），本次仍以它的比值对外。
2. **比值量级 2.7–4.3×**，**V10 最宽**；差异随版本大致增大后趋平（V03 2.7 → V40 4.0）——
   与本仓库「固定成本占比随版本下降」的结构一致。
3. **与 S9d 的关系**：比值的**量级区间未变**（2.5–4.3×）；本仓库自 09-06 起的优化（P0/P2/P2b + 矩阵介质）
   在**本会话内**实测 V40 宿主 ≈ −15%（[S9s §10](S9s-数组介质与字节加速-真实A-B实测.md)），
   但那次收益的**绝对值**已在跨会话噪声内，故此处**不宣称比值被显著拉大**——只报「当前比值 2.7–4.3×」。
4. **可复跑性修复**：`scripts/bench-moonqr.sh` 一条命令出表（S9d 时代只有临时驱动）。

## 5. 局限（诚实标注）

| # | 局限 |
|:-:|------|
| L1 | **单机、单次会话**；R=5 取最小只压采样下限，压不掉会话间漂移（S9q） |
| L2 | 两侧为**独立进程**（同宿主同 N），启动摊销相同但非同一实例内对比 |
| L3 | 只测 `moonqr@0.2.0` 一个版本；包更新后需重跑（脚本已钉版本，改 `MOONQR_VERSION` 即可） |
| L4 | moonqr 的 `encode` 内含**分段优化**（不同于本仓库固定 Byte 段口径），属实现差异、非不公 |
| L5 | 未做跨实现**内容**对齐（不要求 sha256 一致）；只校验尺寸与可编码成功（`ok=N`） |
