## 0. 一句话结论

S1 落地质量高、门禁全绿，但其「不可变式写入」在 **`QRCode::set` 处是假的**——因 MoonBit
`Array` 是引用类型，返回的新 `QRCode` 与源**共享底层数组**，改一处两处都变。已修复为写入前拷贝
数组，并补回归测试（现 32/32×3 全绿）。其余 D1/pub(all)/KEEP_LAST 32 位/错误推迟等拍板项方向正确。

## 3. 发现的问题与优化

### 3.1 【已修复·真实 BUG】`QRCode::set` 别名写穿，破坏「不可变式」语义
- **现象**：`QRCode::set` 内部 `let data = self.data` 后 `data[row*size+col]=m` 再以同一
  `data` 构造新 `QRCode` 返回。MoonBit `Array` 是**引用类型**，故返回的新 QRCode 与源 `self`
  **共享同一底层数组**——调用 `qr2 = qr.set(...)` 会**顺带把 `qr` 也改了**。
- **与声明冲突**：实现记录 §3.4 声称「`QRCode::set` 返回新值」不可变式写入，实为别名写穿。
- **验证**：新增回归测试
  `qr_code_set_immutable_no_alias`（先 `qr.set` 取 `qr2`，再断言源 `qr.get(0,0)` 仍为亮）——
  修复前**失败**（`true != false`），修复后通过。
- **修复**：写入前先 `let data = self.data.copy()`，真正隔离源数组。见本批 PR。
- **影响面**：现无 encode 调用方，故纯 API 正确性问题；S4/S5 若误用共享写会造成难查的耦合
  bug，必须现在修。`.mbti` 公共面未变（内部行为修复，安全重构）。

### 3.2 【已评估·无需改】`QRCode::get/set` 无越界检查
`get(row,col)=data[row*size+col]` 不做范围断言。S1 为骨架、调用方受控（内部/测试），
符合 fast_qr 固定容器契约。**建议**：S4 真正写矩阵时，若担心调试可在 debug 下加断言，
但非 S1 阻塞项。

### 3.3 【已评估·记录】D1 带来的 Module 位语义两处重复（lib / internal）
D1 让 lib `Module`（公共呈现）与未来 `internal/matrix/module.mbt`（算法层字节直算）各自维护
「bit0 明暗 + bit1-3 类型」位布局，**存在漂移风险**。S1 方案已用「同一份位布局文档 + 两端白盒
测试」对冲。**优化建议**：S4 落地 internal/matrix 时，其字节布局务必**复用本 doc 锁定的位规则**
（`序号<<1`），并用与 lib 相同的 Module 白盒断言（抄 module.rs 语义）防漂移——已在 S4 规划中标注。

### 3.4 【已评估·无阻塞】`push_bits` 尾段用 `+` 而其余用 `|`
bitbuffer `push_bits` 收尾部分写残余字节用 `+`（其余段用 `|`）。实测黄金 11 例三后端全绿，
与参考语义一致（该字节为当次新写、无既有位重叠，`+` 不产生进位越位）；但为风格统一与防
未来回归，**建议后续 B6 补丁统一为 `|`**，属可选项（非 bug，因语义等价）。

### 3.5 【已评估·维持】性能观察
- `QRCode::set` 修复后每次 O(size²) 拷贝（31329）。S1 仅容器构造/测试用，量级可接受；
  真正热写发生在 S4 internal/matrix 的原始字节数组上（就地 `mut`），lib 侧仅收尾包装一次。
- bitbuffer 用 `mut len` + 就地改 `Array` 对应 `&mut self`，写入密集路径已按不可变外层/可变内层
  分层，无需改。
