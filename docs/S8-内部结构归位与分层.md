   internal 管线已可跑）；它是「陈旧注释即死文档」缺陷，易误导后续维护与新人接入。
2. **`lib/` 公共层职责未归位**：`qr.mbt`（401 行）内混「结果容器 + 错误 + 容量选择 + 两条编排入口 +

3. **internal 已达标，无需动**：只做「核对性收口」，不改内部包边界、不加新 internal 包（避免过度拆分）。

**S8 定性**：非功能 / 非 M 里程碑，而是「**公共层文件级职责归位 + 入口文档刷新 + 死链/陈旧注释治理**」的

## 3. 拆包判据应用与关键决策

### 3.1 判据逐条应用（框架 §三.2）

> 拆包判据：`.mbt` 过多且分层明显；某内部实现需独立测试且不便走公共 API；
> 公共 API 出现不想进 `.mbti` 的类型。

| 判据 | 对 internal 层 | 对 lib 公共层 |
|------|---------------|--------------|
| `.mbt` 过多且分层明显 | **不触发**：每子包单一职责、6-8 文件 / 包，符合「分文件不拆包」粒度 | **部分触发**：`qr.mbt` 401 行混三类子关注、入口文件失效 → 文件级归位（D11） |
| 内部实现需独立测试且不便走公共 API | **不触发**：各 internal 子包白盒测试齐备 | 不适用（公共层测试用黑盒即足） |
| 公共 API 出现不想进 `.mbti` 的类型 | **不触发**：internal 对模块外不可见；私有 `wrap_packed` 等不 pub，不进 `.mbti` | **不触发**：公共层 `pub(all)` 类型都是有意对外契约 |

**应用结论**：internal 不拆；公共层只做**同包文件级搬移**（不新增包、不动 `.mbti`）。→ 这是 S8 的关键决策
「**S8 = 公共层文件归位，非 internal 再拆包**」。

### 3.2 决策 D11：`qr.mbt` 同包文件级拆分（不建新包、不加新公共类型）

MoonBit 的「包」= 目录（`moon.pkg`），同 `lib/` 内所有 `.mbt` 共享一个命名空间，**文件拆 ≠ 包拆**。
因此在 `lib/` 内把 `qr.mbt` 按子关注拆到独立 `.mbt`，不改 `.mbti`、不改 import、不建新目录，纯提升可读性。
推荐拆法（每拆一个文件即可独立编译）：

```
lib/qr.mbt            → 保留：QRCode 结果容器 + QR_MAX_* 常量 + QRCodeError + 读写访问器
                         （get/set/size/version/ecl/mask/mode/data/meta/default/for_version）
lib/qr_build.mbt      → 新增：容量选择 + 编排入口
                         （select_capacity + build_fixed + build + 私有 wrap_packed）
lib/qr_builder.mbt    → 新增：公共 QRBuilder 构造器（new/from_string + 链式 setter + build）
lib/qr_output.mbt     → 新增：QRCode 输出便捷方法（to_str/print，委托 helpers.print_matrix_with_margin）
```

> ⚠️ **v4 部分回退（2026-09-14，[S11b](./S11b-清理落地记录-v3-v5.md) §12.6）**：
> 上述「输出便捷单独成文件」一条**已被回退**——`qr_output.mbt` 拆出后只承载 2 行转发，
> 而渲染引擎在 `helpers.mbt`，**把「便捷方法」与「被委托的引擎」拆成两个文件反而降低可导航性**。
> v4 已把 `to_str`/`print` 合并回 `lib/helpers.mbt` 并删除该文件（`.mbti` 零变化）。
> **D11 的「结果容器 / 编排 / builder」三分仍然有效**，仅「输出」这一分合并不再单独成文件。

> 拆法按「结果容器 / 编排 / builder / 输出」四个阅读与扩展场景归位。关键点：MoonBit 的「包」= 目录
> （`moon.pkg`），`lib/` 内所有 `.mbt` 共享同一包命名空间，**同包内非 `pub` 符号跨文件亦可见**——
> 故把 `qr.mbt` 的私有 `wrap_packed` 等迁到 `qr_build.mbt` 不破坏内部可见性，且因不新增 `pub(all)`、
> 不改签名，`.mbti`（对外接口快照）**零变化**。这是 S8 敢做纯文件搬移而无行为漂移的依据。
> **护栏**：拆后公共 API 符号集合、签名、`.mbti` 必须与拆前**完全一致**；回归用全量快照全绿证明无行为漂移。

### 3.3 决策 D12：`fast_qr_moonbit.mbt` 从「失效骨架」改为「真实库入口文档头」

- 把文件头那段「项目骨架 / 无逻辑」的失实注释替换为**对当前真实公共面的总览**：列举公共契约所在文件
  （ecl/version/mode/mask/module/qr/helpers/shape/svg）、编排入口（`QRCode::build` / `QRBuilder`）、
  内部管线（constants→bitstream/reedsolomon/data_encoding→matrix→lib 单向链）——使该文件成为**真入口注释**，
  供 IDE/维护者一眼看到库的全貌（MoonBit 无显式 re-export 需要，故保持近空但注释真实即可；若想再导出，
  见 §4 注记）。
- 也可选择把该文件**删除**并把总览并入 `README` 项目结构；但保留空入口 + 真实注释对「消费者 import 本文件
  名语义」更友好（对齐 core feature 包有 `README.mbt.md` 惯用），故**推荐保留并刷新为入口文档**。
- ⚠️ **v4 已改为「删除」（2026-09-14，[S11b](./S11b-清理落地记录-v3-v5.md) §12.3(1)）**：
  刷新后的入口文档头**再次陈旧**（仍写 `S1-S7`、`109 全绿`、`wasm-gc/wasm 双后端`——双后端已在 S9n 收敛），
  证明「源码目录里的纯注释文件」**没有任何门禁能发现其漂移**（`fmt`/`check`/`test`/`coverage`/`mutation`
  全都看不见注释）。删除该文件后 `moon info` 的 `.mbti` **逐字节不变**（实证），
  总览由 README「公共 API 一览」+ `moonbit-实现布局与文件职责.md §3.1` 承载（二者本就更完整）。

### 3.4 决策 D13：internal 层只核对不拆——补 `.mbti` 护栏快照

S8 不做 internal 拆分，但为**固化「接口不漂移」这一 S8 目标**，建议在收尾时显式 `git diff` 比对拆分前后的
`lib/*.mbti`（构建产物，不入库）与既有快照测试，确认零差异。若环境无 moon，则以「公共 `.mbti` 无增删
