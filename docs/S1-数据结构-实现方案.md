## 0. 一句话结论

S1 是**纯数据结构层**（无算法）：把 `Module` 位打包、`QRCode` 固定矩阵容器 + 元数据 +
两类错误、`CompactQR`（→ `bitbuffer`）位流缓冲，以及 `ECL`/`Version` 公共枚举骨架一次落地。
关键架构点在于 **`Module`/`QRCode.data` 的「类型归属与依赖边界」**（§4 决策项），必须先拍板，
否则会触发 internal→lib 反向 import 或 internal 类型泄漏进 `.mbti`。

## 1. S1 范围界定

来自 roadmap §4.2：

> **S1**｜数据结构：Module 打包、QRCode 固定数组、CompactQR、错误类型、公共枚举骨架
> ｜参考 `module.rs` / `qr.rs:25,200` / `compact.rs:61-224` / `version.rs` / `ecl.rs`
> ｜对应黄金 `tests/compact.rs`

**属于 S1（本方案覆盖）**：`ECL`、`Version`（骨架层）、`Module`（位打包 + 访问器）、
`QRCode`（容器 + 元数据 + 错误类型）、`CompactQR`（位流缓冲）。它们对应 roadmap §4.3 的
**B1 / B5 / B6 / B8（骨架部分）+ B2（Version 枚举骨架）**，以及 §4.4 里程碑 **M0** 的数据结构一侧。

**不属于 S1（留待后续批次）**：
- 容量 / 分组 / 格式信息 / GF(256) 等**常量大表**（→ S2：B2 capacity、B3 hardcode、B4 polynomials）
- 三模式编码（→ S3 / B7）
- 功能图案与放置 / 掩码择优（→ S4-S5 / B9-B10）
- 输出层 to_str / SVG（→ S7 / B11）
- 数据放置真正「写矩阵」的时序（需 S4 图案层齐备后才能端到端验证）

> 一句话：S1 只把「数据结构 + 枚举」建好并单测全绿；**不触碰任何依赖表的查表逻辑**
> （表与查表留 S2），以避免 `unused_package` / 半成品门禁问题。

## 3. 各交付物设计要点

### 3.1 `ECL`（lib/ecl.mbt，B1）

- 4 个变体 `L / M / Q / H`，**Q 为默认**（参考接口文档 §1.3，fast_qr 默认 ECL=Q）。
- 需要 `序号映射`：S1 先落一个返回 `Int` 序号（供后续 capacity 表第一维查表用）的访问器。
- MoonBit 若支持给枚举显式值，用 `0..=3`；否则枚举 + `fn to_int(self) -> Int`。

### 3.2 `Version`（lib/version.mbt，B2 骨架）

- 40 变体 `V01..V40`，序号 `0..=39`（Rust 判别值 0-39）。
- 提供 `to_int()` / 序号范围断言。**容量大表放 S2 internal/constants/capacity.mbt**，
  S1 不实现查表，避免提前引入 unused import。

### 3.3 `Mode` / `Mask`（骨架）

- `Mode`: `Numeric / Alphanumeric / Byte`。
- `Mask`: 0-7（`Checkerboard / HorizontalLines / VerticalLines / DiagonalLines /
  LargeCheckerboard / Fields / Diamonds / Meadow`）。
- S1 仅建枚举骨架（供 lib API 面定型），映射逻辑随对应批次（B7/B10）补齐。

### 3.4 `QRCode` 与错误（lib/qr.mbt，B8 骨架）

Rust `QRCode`（qr.rs:25）字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `data` | `[Module; 31329]` | 一维固定数组，按行存储；实际有效 `size*size` |
| `size` | `usize` | `version*4 + 17` |
| `version/ecl/mask/mode` | `Option<...>` | 实际使用值（`Option` 因支持自动选择） |

- **固定容量矩阵**：177×177=31329 模块。MoonBit 用**固定大小容器**（一次分配、零扩容）。
- 错误收敛为两类（对齐 Rust `QRCodeError`）：
  - `EncodedData`：数据超出容量
  - `SpecifiedVersion`：指定版本过小
- S1 落：容器 struct 定义 + 元数据字段 + 错误类型 + 基础构造（仅结构，不含 encode 管线）。

### 3.5 `CompactQR` → `bitbuffer`（B6，internal/bitstream）

来自 [compact-qr.md](./移植参考/专有概念/compact-qr.md)：

| 项 | 语义 |
|----|------|
| `len` | 已写入比特数 |
| `data` | 大端序位流字节容器（高位在前），预分配 |
| `from_version` | 容量 = 版本最大字节数 × 8 比特 |
| `push_bits(bits, len)` | 超出位被 `KEEP_LAST[len]` 截断 |
| `push_u8` | 逐字节写入 |
| `fill()` | 交替写 `0b1110_1100 / 0b0001_0001`（236/17）|

- **平台位宽风险**（roadmap §3.2 / 框架文档 §五.3）：`KEEP_LAST` 在 wasm32=33 项、64 位=65 项。
  MoonBit `wasm`/`wasm-gc`/`js` 后端实现时必须核对截断位数，用显式掩码避免 `usize` 位宽漂移。
- **黄金数据**：抄 `/fast_qr/src/tests/compact.rs`（200 行）期望值转译为白盒断言。

## 4. 关键架构决策（S1 必须先拍板）

> 这是 S1 的核心难点，来自「Module 需进 public 契约（Rust crate 根导出）」与「internal 永不反向
> 依赖 lib / internal 类型不进 `.mbti`」两条布局约束的张力。决策影响 `QRCode.data` 的类型与
> `module.mbt` 的落点，**必须在第一个提交前定案**。

### 现状张力

- Rust：`Module` 是 crate **公共**导出，`QRCode.data: [Module; 31329]`，用户逐行读取拿 Module。
- MoonBit 布局文档 §3.2 / §4：`module.mbt → internal/matrix`，且 **internal 不反向 import lib**、
  **公共枚举只在 lib**、internal 类型不应对 lib 公共接口可见（否则泄漏进 `.mbti`）。
- 若 `QRCode.data` 直接引用 `internal/matrix.Module` → internal 类型泄漏到公共 `.mbti`，违反封装。

### 决策建议（推荐 **D1**，备选 D2）

**D1 — Module 上移为 lib 公共层类型（薄包装），internal/matrix 用「字节」独立实现位操作**
- 在 lib 公共层定义 `Module`（单字节：bit0 明暗 + bit1-3 类型）作为**对外契约/呈现类型**，
  对齐 Rust crate 根导出；`QRCode.data` 用它，用户可读明暗/类型。
- internal/matrix 的放置/掩码/评分**不依赖 lib**，直接对原始 `u8` 字节数组做位运算
  （掩码只 toggle Data、`module_type()` 判类型等用 u8 掩码即可），返回字节结果给 lib；
  lib 侧把字节包装为公共 `Module` 呈现。
- 依赖方向保持：lib → internal/matrix（取字节结果）；internal 不依赖 lib ✓。
- 代价：Module 位语义在 internal（u8 直算）与 lib（薄包装）有轻微重复，用**同一份位布局文档**
  （§3.1 module 位规则）锁死，并用两端白盒测试防漂移。

**D2 — Module 保持在 internal/matrix，QRCode 不直接暴露 Module**
- `QRCode.data` 内部存字节（或私有数组），对外给 `dark_at(row,col): Bool` / `module_type_at(...)` 等
  访问器，不暴露 internal 类型。
- 优点：封装最干净、`QRCode` 不依赖 internal 的类型名。
- 缺点：与 Rust 公共 API 的 `Module` 契约不一致，能力对齐（框架文档 §2.4）略打折；且 S7 渲染/
  S9 输出层仍需逐模块信息，访问器方式可行但 API 面较 Rust 扁平。

> **落地判据**：若追求「与 fast_qr 公共 API 能力对齐」（框架文档 §2.4、验收定义②），推荐 **D1**；
> 若更重视 internal 强封装、公共面最小化，选 **D2**。S1 应选定其一并在 `lib/qr.mbt`、`module.mbt`
> 落地前用 `moon info` 检查 `.mbti`，确认公共面不含 internal 类型。

## 5. 待实测决策（实现时在具备 `moon` 环境逐项验证）

1. **固定大小矩阵**：MoonBit 对 `[UInt8; 31329]` 之类大固定数组的初始化/逃逸开销实测
   （roadmap §3.2 提醒过）；若编译/内存代价高，评估 `Array` 预分配方案。
2. **枚举原始值**：`ECL`/`Version` 能否直接带判别值（如 Rust `= 0 << 1`）；若 MoonBit 不支持，
   用「枚举 + 序号映射函数」方案。
3. **Module 归属**：按 §4 决策 D1/D2 落地后，`moon info` 看 `.mbti` 是否混入 internal 类型。
4. **KEEP_LAST 位宽**：三后端 `wasm-gc`/`wasm`/`js` 下 `push_bits` 截断行为一致（对照框架 §五.3）。
5. **依赖声明时点**：S1 各 `moon.pkg` 的 `import` 只在用到时声明、声明即使用，避免 `unused_package`。
